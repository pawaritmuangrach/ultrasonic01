# Ultrasonic 40 kHz TDOA — จากต้นแบบ 1 TX + 2 RX สู่ Array แทน LiDAR

หลักการและที่มาของสูตรทั้งหมดอยู่ใน [`US015_TDOA_Codex_Spec.md`](US015_TDOA_Codex_Spec.md) เอกสารนี้สรุปเฉพาะสิ่งที่จำเป็นต่อการต่อวงจร รัน และตีความผลลัพธ์

หัวข้อ 1-6 คือต้นแบบเริ่มต้น (1 TX + 2 RX บน Arduino Nano) ที่ build/upload/ทดสอบจริงแล้ว — ถ้าต้องการภาพรวม
การออกแบบขั้นสูงขึ้น (Y-array, MIMO, ทำไม phased array ใช้ไม่ได้, เปรียบเทียบ Nano/ESP32) ข้ามไปหัวข้อ
**[7. จากต้นแบบ TDOA สู่การออกแบบ Ultrasonic Array เต็มรูปแบบ](#7-จากต้นแบบ-tdoa-สู่การออกแบบ-ultrasonic-array-เต็มรูปแบบ-y-array--mimo)** ได้เลย

## 1. Wiring

```
US-015 board 1 (มีตัวส่ง T และตัวรับ R1)
  VCC  -> 5V
  GND  -> GND
  TRIG -> Nano A2
  ECHO -> Nano A0

US-015 board 2 (ถอด/ปิดหัวส่ง ใช้เฉพาะตัวรับ R2)
  VCC  -> 5V
  GND  -> GND
  TRIG -> Nano A2   (สาย TRIG ต่อร่วมกับบอร์ด 1)
  ECHO -> Nano A1
```

A0/A1/A2 ถูกใช้เป็นขา **digital** ล้วน (PC0/PC1/PC2) ไม่มีการเรียก `analogRead()` กับ ECHO เพราะ ECHO เป็นสัญญาณ LOW/HIGH ไม่ใช่ waveform 40 kHz จริง

### 1.1 กรณีใช้ทรานสดิวเซอร์ดิบ (ไม่มี comparator ในตัว)

ถ้าฮาร์ดแวร์ของคุณเป็นทรานสดิวเซอร์ดิบต่อตรงเข้า A0/A1 (ไม่ใช่โมดูล US-015/HC-SR04 สำเร็จรูปที่มีวงจรขยาย+comparator ในตัว) **จะใช้งานไม่ได้** เพราะสัญญาณจาก piezo รับเป็น AC ระดับ mV เท่านั้น ขา digital input จะไม่เห็น echo จริง ต้องเพิ่มวงจร analog front-end ต่อหน้า A0/A1 แต่ละช่อง ประกอบด้วย 4 สเตจ (ทรานซิสเตอร์ NPN ทั่วไป 4 ตัว/ช่อง):

1. ขยายสัญญาณ 2 สเตจ (common-emitter amplifier, AC-coupled)
2. Envelope detector (ใช้ขา Base-Emitter ของทรานซิสเตอร์อีกตัวแทนไดโอด + ตัวเก็บประจุ)
3. Threshold switch (ทรานซิสเตอร์อีกตัวทำหน้าที่เทียบระดับแทน comparator IC)

วงจรนี้ **output จะ idle ที่ HIGH แล้วลง LOW เมื่อพบสัญญาณ** (กลับด้านกับโมดูลสำเร็จรูป) โค้ดมี flag `ECHO_ACTIVE_LOW` (ตั้งเป็น 1 ไว้แล้วในไฟล์ .ino) เพื่อรองรับ polarity แบบนี้ — ถ้าเปลี่ยนไปใช้โมดูลสำเร็จรูปจริงในอนาคต ให้ตั้งกลับเป็น 0

แนะนำจัดวางแบบสมมาตรสำหรับ calibrate:

```
R1        T        R2
|---------|---------|
      แผ่นสะท้อนเรียบ 30-50 cm ด้านหน้า
```

## 2. Flash และเปิด Serial

1. เปิด `ultrasonic_tdoa_nano/ultrasonic_tdoa_nano.ino` ด้วย Arduino IDE, เลือกบอร์ด "Arduino Nano" / processor ATmega328P (เก่า ถ้า upload ไม่ผ่านให้ลอง "ATmega328P (Old Bootloader)")
2. Upload
3. เปิด Serial Monitor/Serial Plotter ที่ **115200 baud** — หรือใช้หน้าเว็บ simulation ใน `simulation/index.html` แทน (ดูหัวข้อ 6)

ค่าเริ่มต้นของ output คือ **CSV** (ส่ง `s` ทาง Serial เพื่อสลับเป็น human-readable)

Header ของ CSV:

```
timestamp_ms,r1_pulse_us,r2_pulse_us,r1_cm,r2_cm,raw_dt_us,calibrated_dt_us,path_diff_cm,angle_deg,confidence,status,cycle_shift
```

ตัวอย่างบรรทัดข้อมูล:

```
1250,212.5,230.5,3.64,3.95,18.0,18.0,0.617,7.10,91,VALID,0
```

Human-readable (หลังส่ง `s`):

```
R1=212.5us 3.64cm | R2=230.5us 3.95cm | raw_dt=18.0us | calibrated_dt=18.0us | path=0.617cm | angle=7.10deg | confidence=91 | status=VALID | cycle_shift=0
```

## 3. Serial Commands

| คำสั่ง | ผลลัพธ์ |
|---|---|
| `c` | เริ่ม calibration (เก็บ ~200 samples แล้วหา median offset ของ raw dt) — **ต้องวางอุปกรณ์สมมาตรตามรูปด้านบนก่อนส่งคำสั่งนี้** |
| `p` | พิมพ์ parameters ปัจจุบัน (sound speed, spacing, offset, output mode) |
| `r` | ล้าง median-filter / cycle-slip history |
| `s` | สลับ CSV <-> human-readable |
| `t25` | ตั้งอุณหภูมิ 25 °C แล้วคำนวณความเร็วเสียงใหม่ |
| `d5.0` | ตั้ง receiver spacing เป็น 5.0 cm |

## 4. สมการหลัก

```
pulse_us          = fall_tick - rise_tick   (Timer1, 0.5 us/tick)
distance_cm       = pulse_us * c / 2                      (ระยะแบบ pulse-echo ปกติ)
raw_dt_us         = pulse2_us - pulse1_us
calibrated_dt_us  = raw_dt_us - calibration_offset_us      (+ cycle-slip correction)
path_diff_cm      = calibrated_dt_us * c                   (ไม่หาร 2 เพราะเทียบเส้นทางถึงตัวรับสองตัว)
max_dt_us         = receiver_spacing_cm / c                 (ขอบเขตทางฟิสิกส์)
angle_deg         = asin(path_diff_cm / receiver_spacing_cm) * 180/pi   (เฉพาะเมื่อ status == VALID)
```

`c = 0.0343 cm/us` ที่อุณหภูมิห้อง (ปรับได้ด้วยคำสั่ง `t<celsius>`)

## 5. ข้อจำกัดสำคัญ (อ่านก่อนเชื่อผลลัพธ์)

1. US-015 เป็น black-box — ECHO ที่เห็นคือผลหลัง comparator/threshold ภายในโมดูล ไม่ใช่ raw 40 kHz waveform
2. `raw_dt_us` **ไม่รับประกัน** ว่าเท่ากับส่วนต่างเวลาที่คลื่นมาถึงจริง เพราะแต่ละบอร์ดมี internal delay/threshold ไม่เท่ากัน — ต้อง calibrate (`c`) ก่อนเสมอ
3. Calibration ลบ static offset ได้ แต่ลบ dynamic jitter ไม่ได้ทั้งหมด
4. `cycle_shift != 0` แปลว่าเกิด cycle-slip correction (ค่ากระโดดเป็นทวีคูณของ 25 us) — เป็น heuristic ไม่ใช่การพิสูจน์
5. `angle_deg` ใช้สมมติฐาน far-field / plane-wave ถ้าวัตถุอยู่ใกล้มาก มุมนี้จะไม่แม่น
6. ผลลัพธ์ทั้งหมดควรเรียกว่า **pseudo-TDOA** ไม่ใช่ true TDOA จนกว่าจะเข้าถึง raw receiver signal ได้จริง (ดูหัวข้อ 27 ในสเปก)
7. ไม่ควรใช้ระบบนี้ในงาน safety-critical

## 6. Real-time 2D wave simulation

`simulation/index.html` เป็นหน้าเว็บ (self-contained, ไม่ต้องติดตั้งอะไร) ที่:

- ต่อกับ Arduino ผ่าน **Web Serial API** (Chrome/Edge เท่านั้น) ที่ 115200 baud
- อ่านบรรทัด CSV ทีละแถว แล้ววาดภาพ 2D: ตำแหน่ง T/R1/R2, คลื่นวงกลมที่ขยายตัวออกจาก T ไปกระทบวัตถุ (คำนวณตำแหน่งวัตถุจาก r1_cm และระยะ target->R2 ที่แปลงจาก r2_pulse_us) แล้วมีคลื่นสะท้อนกลับไปหา R1 และ R2 พร้อม timing สัมพัทธ์ตามข้อมูลจริง (สโลว์โมชันเพื่อให้ตามองเห็น)
- มีปุ่ม **Demo mode** สำหรับดูตัวอย่างการทำงานโดยไม่ต้องต่อ Arduino จริง
- **สะสมจุดสะท้อนทุกจุดที่ตรวจพบ** (ไม่ใช่แค่ ping ล่าสุด) เป็นแผนที่จุดสีชมพูบานเย็น (magenta point cloud) คล้าย
  scatter plot ของ SLAM map — จุดที่วัดได้ต่อเนื่องกันและอยู่ใกล้กัน (<15 cm) จะมีเส้นเชื่อมให้ดูเป็นขอบวัตถุ/กำแพงคร่าวๆ
  เอาเมาส์ชี้จุดใดก็ได้เพื่อดูระยะ/มุม/confidence ของจุดนั้น มีปุ่ม "Clear Map" และ "Export Map (CSV)"
  หมายเหตุ: เซนเซอร์ชุดนี้ไม่ได้หมุนสแกนแบบ lidar การจะได้แผนที่ห้องเต็มรูปแบบต้องเลื่อน/หมุนวัตถุหรือตัวเซนเซอร์เอง
  แล้วเก็บผลสะสมไว้ (เหมาะกับ Experiment 4 ในสเปก)

วิธีใช้:

1. อัปโหลดโค้ดลง Arduino Nano และปิด Serial Monitor ใน Arduino IDE ก่อน (พอร์ตใช้ได้ทีละโปรแกรม)
2. เปิด `simulation/index.html` ด้วย **Chrome หรือ Edge** (ดับเบิลคลิกเปิดไฟล์ได้เลย ไม่ต้องมี server)
3. กดปุ่ม "Connect Arduino" แล้วเลือกพอร์ต COM ของ Nano
4. ดูคลื่นวิ่งแบบ real-time ทุกครั้งที่ Arduino ยิงคลื่นออกไป

ถ้าต้องการดูตัวอย่างก่อนต่อฮาร์ดแวร์จริง ให้กด "Demo mode (no hardware)" แทน

## 7. จากต้นแบบ TDOA สู่การออกแบบ Ultrasonic Array เต็มรูปแบบ (Y-array + MIMO)

หัวข้อ 1-6 ด้านบนคือต้นแบบเริ่มต้น (1 TX + 2 RX, US-015/front-end แบบ discrete transistor) ต่อมาโปรเจกต์ขยายเป้าหมาย
เป็น **ใช้ ultrasonic array แทน LiDAR** สำหรับ obstacle avoidance ระยะใกล้ (เทรน NN โดยใช้กล้องเป็น ground truth)
หัวข้อนี้สรุปข้อค้นพบและการออกแบบที่ได้จากการสำรวจแนวทางต่างๆ

### 7.1 ทำไมตัวส่งหลายตัว + ตัวรับตัวเดียว (phased array) ใช้ไม่ได้

แนวคิดแรกที่พิจารณาคือใช้ตัวส่งหลายตัวรวมคลื่นเป็นลำแคบแล้วกวาดทิศทาง (transmit beam steering) แต่พบข้อจำกัดทาง
ฟิสิกส์ที่แก้ไม่ได้:

- ที่ 40kHz, c=343 m/s → ความยาวคลื่น **λ ≈ 8.575mm** → ต้องวางตัวส่งห่างกันไม่เกิน **λ/2 ≈ 4.3mm** ถึงจะไม่เกิด
  ลำคลื่นหลอก (grating lobe)
- ทรานสดิวเซอร์ TCT40-16 มีตัวถังจริง **16mm** — ใหญ่กว่าที่ต้องการเกือบ 4 เท่า และไม่มีทางวางให้ใกล้กว่านี้ได้
  เพราะเป็นขนาดจริงของอุปกรณ์ในอากาศ
- ทดสอบด้วยการจำลอง (`simulation/beamforming_compare.html`) ยืนยันว่าที่ระยะ 16mm ยิงพร้อมกันเกิดลำคลื่นแรง
  พร้อมกัน **3 ทิศ** (-32°, 0°, 32°) และถ้าพยายาม steer ไป 20° ด้วยการหน่วงเวลา จะยิ่งแย่ลงเป็น **4 ทิศ**
  (-47°, -11°, 20°, 61°)
- **ปัญหานี้แก้ด้วยซอฟต์แวร์ไม่ได้เลย** เพราะพลังงานเสียงกระจายผิดทิศไปแล้วตั้งแต่ในอากาศ ไม่ใช่ความผิดพลาดของ
  การประมวลผลสัญญาณ

สรุป: ตัวส่งหลายตัวยิงพร้อมกันเพื่อเล็งลำคลื่นไม่ใช่ทางที่ไปได้กับทรานสดิวเซอร์ขนาดนี้

### 7.2 ทางที่เลือกแทน: TDOA (วัดเวลา ไม่ใช่วัดเฟส)

แทนที่จะเล็งลำคลื่นตอนส่ง เปลี่ยนมายิงคลื่นกระจายกว้างครั้งเดียว แล้วใช้ **ตัวรับหลายตัว** ฟังพร้อมกัน คำนวณทิศทาง
จากผลต่างเวลาที่เสียงมาถึงแต่ละตัว (`sinθ = c·Δt/d`) สมการนี้มีคำตอบเดียวเสมอ (วัดเวลา ไม่ใช่เฟสที่วนซ้ำทุกคาบ)
จึง**ไม่มี grating lobe** — เป็นเหตุผลที่ต้นแบบในหัวข้อ 1-6 ใช้สถาปัตยกรรมนี้มาตั้งแต่แรก

กฎของ aperture ก็กลับด้านจาก phased array: ความละเอียดเชิงมุม `θ_res ≈ λ/D` → **ยิ่งตัวรับกระจายกว้าง (D ใหญ่)
ยิ่งแยกมุมได้ละเอียด** ตรงข้ามกับ phased array ที่ต้องการให้ชิดกัน

### 7.3 ขยายเพิ่มด้วย MIMO (coded TX หลายตัว)

ยิงตัวส่งหลายตัว**พร้อมกัน**โดยแต่ละตัวใช้ code ต่างกัน (แยกด้วย matched filter ฝั่งรับ) จะได้เส้นทางข้อมูล
(TX→วัตถุ→RX) แยกกันได้ = จำนวน TX × จำนวน RX (virtual array, ตำแหน่งเสมือน = ตำแหน่ง TXi + RXj) — ได้ข้อมูล
เพิ่มแบบ**ทวีคูณ**จากอุปกรณ์ที่เพิ่มแบบบวก และยังยิงครั้งเดียวจบเหมือนเดิม (ไม่ช้าลง เพราะยิงพร้อมกัน) ต่างจาก
การยิงตัวส่งทีละตัว (reciprocity ให้ข้อมูลเท่ากันแต่ช้ากว่า 6 เท่าและวงจรซับซ้อนกว่า จึงไม่คุ้ม)

### 7.4 ผังที่แนะนำ: Scaled Array — 3 TX + 9 RX (12 อุปกรณ์จริง, 27 เส้นทางเสมือน)

- **TX1-TX3**: กลุ่มสามเหลี่ยมเล็กกึ่งกลางแผง (รัศมี 14mm จากศูนย์กลาง — ห่างพอให้ตัวถัง 16mm ไม่ชนกัน)
- **RX1-RX9**: 3 แขนมุม 120° (แบบเดียวกับผัง VLA radio telescope เพื่อ sampling มุมสม่ำเสมอทุกทิศ) แขนละ 3 ตัว
  ที่ระยะ **40 / 80 / 140mm** (140mm คือตัวขยายใหม่จากเดิม 40/80mm)
- แต่ละแขนให้ทั้งข้อมูล azimuth (ซ้าย-ขวา) และ elevation (บน-ล่าง) พร้อมกัน
- Diminishing returns: ขยายรัศมี 40→60mm ได้ θ_res ดีขึ้น 2.05° แต่ขยาย 140→160mm ได้แค่ 0.22° (จึงหยุดที่ 140mm)
- Circuit BOM เต็มระบบ: TX driver (TC4427A) 3 ชุด, MCP6024 (quad op-amp, 2 RX/ชิป) 5 ชิป, วงจร VREF 2.5V 1 ชุด
  (ใช้ร่วมกันได้ทุกช่อง)

### 7.5 ข้อจำกัดของแพลตฟอร์มควบคุม (Nano / ESP32 / ESP32+ADS1115)

| แพลตฟอร์ม | RX สูงสุดที่ใส่ได้จริง | จับ raw chirp 40kHz ได้ไหม | MIMO coded TX |
|---|---|---|---|
| Arduino Nano | ≤6-7 (จาก 8 ขา A0-A7) | ไม่ได้ (ADC มัลติเพล็กซ์ช้าเกิน) → ใช้ envelope+threshold แทน | ไม่ไหว |
| ESP32 เดี่ยว | 8 (ADC1) | ได้ (DMA ~100-500kS/s) | ได้ 3 ตัวเต็มรูปแบบ |
| ESP32 + ADS1115 | 8 + 4 (I2C) | เฉพาะช่อง ESP32; ADS1115 ช้าเกิน (860 SPS) ใช้ได้แค่ envelope | ได้ 3 ตัว |

**สรุป**: ผัง 3TX+9RX เต็มรูปแบบต้องใช้ ESP32+ADS1115 แบบ hybrid (RX 8 ช่องแรกจับ raw waveform ผ่าน ESP32,
RX "far" 140mm ที่เหลือจับแค่ envelope ผ่าน ADS1115) — Nano ทำได้แค่ 1TX+6RX แบบ envelope เท่านั้น

### 7.7 ข้อจำกัดที่ยังเหลืออยู่

**Cycle slip**: คลื่น 40kHz คาบ 25µs ถ้าวัดเวลาไม่แม่นพอ ระบบอาจสับสนว่าจับคลื่นลูกไหน (ค่ากระโดดเป็นก้อนละ ~25µs
— ปรากฏการณ์เดียวกับที่เจอจริงตอน calibrate ฮาร์ดแวร์ในหัวข้อ 2-3) ต่างจาก grating lobe ตรงที่**แก้ได้** ด้วย:

1. Chirp + Pulse Compression (แผนระยะยาว) — กวาดความถี่แทนโทนเดียว ทำให้วัดเวลาคมขึ้นมาก
2. วางตัวรับแบบ sparse/non-redundant — ความกำกวมของแต่ละคู่ตกคนละมุม ไม่ทับกัน
3. Neural Network + กล้องเป็น ground truth — เรียนรู้ล้างส่วนที่เหลือจากข้อมูลจริง

**ข้อจำกัดที่ต้องยอมรับ**: อัลตราโซนิกในอากาศไม่มีวันเทียบ LiDAR ได้ในเรื่องระยะไกล (สิบ-ร้อยเมตร) และความละเอียด
ระดับ mm — เป้าหมายที่สมจริงคือใช้แทนได้เฉพาะบริบท obstacle avoidance ระยะใกล้ (<5-10m) เท่านั้น

| ความคลาดเคลื่อนคงที่ | **1.25 ms = ระยะผิด 21 cm** |

เริ่มนับ ตัวอย่างแรกที่ได้จริงไม่ได้เกิดขึ้น ณ วินาทีนั้น **ถ้าเชื่อเวลาของซอฟต์แวร์ ทุกระยะจะเพี้ยนไป

อยู่ในทั้งสองพจน์เท่ากัน

วัดระยะซ้ำ 8 ครั้งกับวัตถุเดียวกันได้ **40.6 cm ± 7.3 mm**

> ข้อสังเกตที่สำคัญต่อ Stage 2: การกระจายของ**ผลต่าง** (42.4 µs) แย่กว่าการกระจายของ
> **เวลาสัมบูรณ์ของเอคโค่** (37.5 µs) ทั้งที่การลบควรหักสิ่งที่ร่วมกันออก แปลว่าตัวจำกัดความแม่น

> Stage 2 ที่ใช้ cross-correlation บนเฟสจะแก้ตรงนี้ ไม่ใช่การไปไล่แก้ทริกเกอร์ให้นิ่งขึ้น

### 8.8 โซนบอด — ความยาว burst เปลี่ยนระยะที่อ่านได้

วางแผ่นสะท้อนที่ 20 cm นิ่งๆ แล้วเปลี่ยนเฉพาะความยาว burst อย่างเดียว:

| รอบ | ยอดพัลส์ตรง | เวลาไต่ขึ้น | ระยะที่อ่านได้ | SNR |
|---|---|---|---|---|
| 1 | 676 mV | 43 µs | 5.1 cm | 15.7 dB |
| 2 | 627 mV | 160 µs | 6.0 cm | 22.3 dB |
| 3 | 987 mV | 210 µs | 10.5 cm | 28.7 dB |
| **4** | 907 mV | 229 µs | **19.5 cm** | 29.6 dB |
| 6 | 1373 mV | 295 µs | 22.5 cm | 34.4 dB |
| 8 | 1575 mV | 377 µs | 23.9 cm | 37.7 dB |

**แผ่นไม่ได้ขยับ สิ่งที่ขยับคือหางเสียงของตัวส่ง** TCT40 เป็นเรโซเนเตอร์ Q สูง ยิงยาวขึ้น
หางก็ยาวขึ้น อะไรที่มาถึงใต้หางนั้นจะถูกอ่านช้ากว่าจริงหรือหายไปเลย

นี่คือ **โซนบอด (blind zone)** ซึ่งเป็นข้อจำกัดเชิงกายภาพ ไม่ใช่บั๊ก:

```
โซนบอด ≈ (ความยาว burst + เวลาหางลง) × c / 2
4 รอบ → เคลียร์ที่ ~15 cm     8 รอบ → เคลียร์ที่ ~24 cm
```

แลกกันตรงๆ: **burst สั้น = เห็นของใกล้ได้ · burst ยาว = SNR ดีกว่า ~8 dB**
คำสั่ง `b <cycles>` เปลี่ยนได้ตอนรัน ไม่ต้องแฟลชใหม่

> ข้อนี้กระทบการออกแบบแผงใน Stage 4 โดยตรง: ยิ่งหัวส่งกับหัวรับอยู่ใกล้กันและยึดบนวัสดุแข็ง
> เดียวกัน พัลส์ตรงยิ่งแรงและหางยิ่งยาว โซนบอดก็ยิ่งกว้าง — เป็นเหตุผลเชิงตัวเลขที่ต้องใส่
> ยางรองแยกทรานสดิวเซอร์ออกจากแผง ไม่ใช่แค่ "ทำแล้วดี"

ยอดเด่นล็อกอยู่ที่ **38.2 / 40.4 / 41.6 kHz** ตรงย่านเรโซแนนซ์ของ TCT40 พอดี และ
**ในย่านแรงกว่านอกย่าน 43 เท่า** — ตัวกรองนี้มาจากตัวทรานสดิวเซอร์เอง ไม่ใช่จากวงจร

> ⚠️ แอมพลิจูดของการเขย่ากุญแจ**ไม่ซ้ำรอย** หกช็อตในการเขย่าครั้งเดียวได้ 48-112 mV
> (ต่างกัน 2.3 เท่า) จึงใช้เทียบ "มี/ไม่มีสัญญาณ" ได้ แต่**ใช้วัดเกนไม่ได้** ตัวเลข 337 mV
> ของบอร์ดเดิมกับ 112 mV ของบอร์ดใหม่ไม่ได้บอกว่าเกนต่างกัน — บอกแค่ว่าเขย่าคนละแรง

### 8.10 Stage 1 ปิดจบ — ภาคส่งบนบอร์ดขวา และการวัดระยะที่ตามสูตรจริง

ผังใหม่: บอร์ดซ้าย = RX · บอร์ดขวา = TX · ESP32 เสียบคร่อมกลาง · ขาขับย้ายไป **GPIO18**
เซ็นเซอร์อยู่บนแผงพิมพ์ 3D: **หัวส่งที่รู A40 หัวรับที่รู A140 ห่างกัน 100 มม.**
(เดิมแผนคือ T1 แต่สายไฟยาวไม่ถึง — ร่องตัดเสียงที่รัศมี 110 มม. เลยอยู่คั่นกลางพอดี)

#### ความผิดพลาดที่ทำให้เสียเวลาไปหนึ่งชั่วโมง

ต่อบอร์ด TX เสร็จแล้ว **ESP32 เงียบสนิท** ไม่ตอบอะไรเลย แม้แต่ข้อความบูตของ ROM

วิธีที่ใช้ไล่: ถอดสายที่เชื่อม ESP32 ออกทั้งหมด → กลับมาทำงาน → เสียบกลับทีละชุด
เจอว่า**สาย 5V คือตัวปัญหา** — ผังภาคส่งเป็นภาพของบอร์ดขวา แต่เขียนกำกับว่า
"5V มาจากบอร์ดซ้าย แถว 60 รู H" ซึ่งอ่านแล้วไปหยิบแถว 60 ของ**บอร์ดที่กำลังดูอยู่**
และแถว 60 ของบอร์ดขวาคือ **CLK — สายนาฬิกาของแฟลชในตัวชิป**

> **บทเรียน**: เลขแถวเดียวกันมีอยู่บนบอร์ดทั้งสองอันและหมายถึงคนละขา ผังที่แสดงบอร์ดเดียว
> จึงห้ามอ้างอิงรูบนอีกบอร์ดด้วยข้อความ — ต้องมีผังที่เห็นทั้งสองบอร์ดพร้อมกัน
> จึงทำ `diagrams/rig_2_esp32_pinmap.svg` ขึ้นมา

อาการ "ศูนย์ไบต์" ยังใช้ตัดสาเหตุได้ด้วย: ถ้า TX0 โดนกดลงกราวด์ ตัวรับจะพ่นไบต์ 0x00 รัวๆ
ไม่ใช่เงียบ — เงียบสนิทแปลว่าสายอยู่ในสถานะพัก คือตัวชิปไม่ทำงานเลย

#### ผลวัด

| | ค่า |
|---|---|
| พื้นเสียงรบกวน | 0.9-1.1 mV |
| ความถี่พาหะของเสียงสะท้อน | **41.72 kHz** |
| พัลส์ตรง TX→RX (100 มม.) | 258 ± 23 µs · 6.4 mV |
| ความเสถียรของขอบขึ้น | **± 6.8 µs = ± 1.2 มม.** |

**พัลส์ตรงเบากว่าเสียงสะท้อน 59 เท่า และนั่นถูกต้อง** — หัวส่งกับหัวรับหันหน้าไปทางเดียวกัน
เส้นทางตรงจึงอยู่ที่ 90° นอกแกนของทั้งคู่ (≈ −60 dB) ส่วนเสียงสะท้อนอยู่บนแกนทั้งไปและกลับ
เสียแค่การกระจาย 1/r² กับการสะท้อน (≈ −22 dB) ผลต่างที่คำนวณได้ 38 dB = 79 เท่า

#### ระยะเลื่อนตามสูตรจริง

เรขาคณิตเป็นแบบ bistatic (หัวส่ง-หัวรับห่างกัน B = 100 มม.) ระยะทางเดินคือ `√((2d)² + B²)`

| ระยะไม้บรรทัด | ขอบขึ้นที่ควรได้ | วัดได้ | ต่าง |
|---|---|---|---|
| 20 ซม. | 1538 µs | 1522 µs | −2.8 มม. |
| 30 ซม. | 2110 µs | 2036 µs | −12.6 มม. |
| 53 ซม. | 3440 µs | 3531 µs | +15.5 มม. |

`c = 343 m/s` ตายตัว · ค่าคลาดคงที่ **τ₀ = 336 µs** · **rms 11.7 มม. บนช่วง 33 ซม.**

**การทดสอบที่สำคัญที่สุดคือการทำนายล่วงหน้า**: หลังวัดที่ 20 กับ 53 ซม. เสร็จ ล็อกค่า τ₀
แล้วประกาศไว้ก่อนว่าถ้าวางที่ 30 ซม. ขอบขึ้นต้องอยู่ที่ **2093 µs** — วัดจริงได้ **2036 µs**
**พลาดไป 9.8 มม.**

ค่าคลาดเคลื่อน 11.7 มม. ใหญ่กว่าความเสถียร (1.2 มม.) สิบเท่า จึงเป็นความคลาดเชิงระบบ
ไม่ใช่สัญญาณรบกวน — แผ่นสะท้อนยังไม่มีที่ยึด วางแล้วเอียงได้ และวัดด้วยไม้บรรทัดมือถือ
(ผู้ใช้วัดใหม่พบว่าตำแหน่ง "50 ซม." จริงๆ คือ 53 ซม. ตรงกับที่โมเดลทำนายไว้ว่า ~55 ซม.)

> τ₀ = 336 µs มาจากสองส่วน: เวลาไต่ขึ้นของ TCT40 ที่วัดได้เอง 230-240 µs (ระยะจากขอบถึงยอด)
> บวกความคลาดของจังหวะยิงเทียบกับ DMA ที่วิ่งอิสระ ซึ่งเป็นเหตุผลที่หัวไฟล์ `esp32_scope.ino`
> เขียนไว้ตั้งแต่แรกว่า t=0 ที่แท้จริงต้องอ่านจากพัลส์ตรงในข้อมูล ไม่ใช่จากจังหวะที่ซอฟต์แวร์สั่ง

### 8.11 ช่องรับที่ 2 — ทำงาน แต่เสียงรบกวนสูงกว่า 3 เท่า

ต่อช่องที่ 2 บนบอร์ดที่สาม ป้อน VREF และกราวด์ข้ามมาจากบอร์ด RX ขาออกเข้า GPIO35

**สิ่งที่ผ่าน**

| | ช่อง 1 (GPIO34) | ช่อง 2 (GPIO35) |
|---|---|---|
| ไบแอส | 1519.9 mV | 1521.5 mV |
| ชนราง | 0 / 0 | 0 / 0 |
| 50 Hz | 0.31 mV | 1.74 mV |
| เห็นเอคโค่ | ใช่ ที่ +2147 µs | ใช่ ที่ +2240 µs |

ไบแอสสองช่องต่างกัน **1.6 mV** พิสูจน์ว่าสาย VREF ข้ามบอร์ดทำงาน และช่องที่ 2 เห็นเอคโค่
ที่เวลาถูกต้อง วงจรใช้ได้

**สิ่งที่ไม่ผ่าน** — วัดเสียงรบกวนของวงจรล้วนๆ (`q` ไม่ยิงเบิร์สต์) ที่ 1 MS/s เฉลี่ย 6 เฟรม

| ย่าน | 10-20k | 30-50k | 60-90k | 90-130k | 130-200k |
|---|---|---|---|---|---|
| ช่อง2/ช่อง1 | 2.95 | 3.61 | 2.64 | 2.88 | 2.76 |

และเอคโค่ของช่อง 2 แรงกว่า **4.04 เท่า** (1359 mV ต่อ 336 mV)

**การวินิจฉัยที่ผิดรอบแรก และวิธีที่จับได้ว่าผิด**

รอบแรกสรุปว่า Rf เป็น 180k แทน 100k เพราะเกนสูงขึ้น 3 เท่า — **ผิด** จับได้ตอนใส่ขั้วของ
ออปแอมป์เข้าไปในโมเดล เกนกับแบนด์วิดท์แลกกันเสมอ ถ้าเกนสูงขึ้น 3 เท่า แบนด์วิดท์ต้องแคบลง
3 เท่า อัตราส่วนจึงต้อง**ตกลงตามความถี่** (โมเดลทำนาย 4.16 ที่ 15 kHz ลงเหลือ 1.22 ที่ 165 kHz)
แต่ที่วัดได้**แบนราบ** ทุกสมมติฐานที่แตะเกนให้ค่าคลาดอย่างน้อย 1.17 ทั้งหมด

> บทเรียน: ฟิตตัวเลขเดียว (อัตราส่วนที่ 40 kHz) ได้คำตอบสวยเสมอ **รูปทรงเทียบความถี่**
> ต่างหากที่แยกสมมติฐานออกจากกัน ถ้ารอบแรกผมพล็อตทั้งแถบก่อนสรุปก็คงไม่พลาด

**คำอธิบายที่เข้ากับข้อมูลทุกตัว: R ไบแอส เป็น 100 kΩ แทนที่จะเป็น 10 kΩ**

| หลักฐาน | R ไบแอส 100k ทำนายว่า | วัดได้ |
|---|---|---|
| เสียงรบกวน | √(100/10) = **3.16 เท่า** | 2.97 เท่า |
| รูปทรงเทียบความถี่ | **แบนราบ** (เสียงความร้อน ไม่เกี่ยวแบนด์วิดท์) | แบนราบ |
| เกน / แบนด์วิดท์ | **ไม่เปลี่ยน** (เกน = 1 + Rf/Zg ไม่มี R ไบแอส) | ไม่เปลี่ยน |
| ความแรงเอคโค่ | **~4 เท่า** ถ้าหัวรับมี Z ราว 50 kΩ | 4.04 เท่า |

หัวรับเป็นแหล่งจ่ายอิมพีแดนซ์สูง R ไบแอสจึงทำตัวเป็นตัวแบ่งแรงดันกับมัน
ค่า 10k ทิ้งสัญญาณไปมาก ค่า 100k ทิ้งน้อยกว่า — สัญญาณแรงขึ้นแต่เสียงรบกวนแรงขึ้นพอกัน
จึงไม่ได้ SNR ดีขึ้นเลย

**โปรเจกต์นี้เคยพลาดตรงนี้มาแล้วครั้งหนึ่ง** — `diagrams/README.md` บันทึกไว้ว่า R ไบแอส
เคยเป็น 100 kΩ แล้วแก้เป็น 10 kΩ ตอนไล่ฮัม 50 Hz ตัว 100k ที่หยิบมาใส่บอร์ดใหม่จึงน่าจะ
เป็นตัวเดิมที่ถอดออกมาแล้ววางปนอยู่

**ต้องแก้ ไม่ใช่คาลิเบรตออก** เพราะเครือข่ายอินพุตที่ต่างกันเปลี่ยน**เฟส**ที่ 40 kHz ด้วย
ไม่ใช่แค่ขนาด และเฟสที่ต่างกันคือ Δt ที่ผิดโดยตรง (1° ที่ 40 kHz = 0.069 µs)

**ผลจริง: R ไบแอสวัดด้วยมัลติมิเตอร์ได้ 10 kΩ — สมมติฐานนี้ก็ผิดอีก**

ตัวจริงอยู่ที่**หัวรับ** ไม่ใช่วงจร จับได้ด้วยการกวาดความถี่พาหะ (`s <hz>` 36-44 kHz)
แล้ววัดยอดเอคโค่ หัวส่งเป็นตัวเดียวกันทั้งสองช่อง ความต่างจึงเป็นของหัวรับล้วนๆ

| ยิงที่ (kHz) | 36 | 38 | 40 | 41 | 42 | 43 | 44 |
|---|---|---|---|---|---|---|---|
| ช่อง 1 (mV) | 63 | 151 | 334 | 380 | 366 | 332 | 263 |
| ช่อง 2 (mV) | 300 | 394 | 930 | 1173 | 1234 | 1200 | 1013 |

**ยอดของช่อง 1 อยู่ที่ 41.27 kHz · ช่อง 2 อยู่ที่ 42.14 kHz · ต่างกัน 874 Hz**

(เป็นค่าต่ำสุดที่เป็นไปได้ เพราะยอดที่วัดคือผลคูณของ TX กับ RX หัวส่งที่ใช้ร่วมกัน
ดึงยอดทั้งสองเข้าหากัน f0 ของหัวรับจริงจึงห่างกันมากกว่านี้)

**ทำไม 874 Hz ถึงเป็นเรื่องใหญ่** กระป๋องพวกนี้ Q สูง เฟสจึงกวาดเร็วรอบเรโซแนนซ์
ที่ Q=20 ความต่าง 874 Hz ให้เฟสต่างกัน 12.9° ที่ 40 kHz = **Δt 0.90 µs = 89% ของงบ Stage 2**
ใหญ่กว่าทุกเรื่องที่เราถกกันมาเรื่องออปแอมป์

**และห้ามย้ายไปยิงที่ความถี่ที่แรงที่สุด**

| ยิงที่ | เฟสต่าง | Δt | ความแรง ช.1 |
|---|---|---|---|
| 38k | −3.2° | 0.22 µs | 151 mV |
| **40k** | −12.9° | **0.89 µs** | 334 mV |
| 41k | −32.6° | **2.26 µs** | 380 mV ← แรงสุด |
| 42k | −42.9° | **2.98 µs** | 366 mV |

**ความถี่ที่ให้สัญญาณแรงที่สุดคือความถี่ที่เฟสเพี้ยนที่สุด** เพราะระหว่างเรโซแนนซ์สองตัว
เฟสของทั้งคู่วิ่งสวนทางกัน ย้ายไป 41.5 kHz เพื่อสัญญาณแรงขึ้น 14% แลกกับ Δt พังไป 2.5 เท่าของงบ
40 kHz ที่ใช้อยู่บังเอิญเป็นจุดที่ดีอยู่แล้ว **ห้ามย้าย**

**ทางแก้: คัดหัวรับ** ไม่ใช่ซ่อมวงจร มี `tools/match_transducers.py` วัด f0 ทีละตัว
บนช่องเดียวกัน บอร์ดเดียวกัน หัวส่งเดียวกัน แล้วจัดชุดที่ f0 ใกล้กันที่สุด

| f0 ต่างกัน | เฟสที่ 40 kHz | Δt |
|---|---|---|
| 874 Hz (ตอนนี้) | 12.9° | 0.90 µs |
| 400 Hz | 7.1° | 0.50 µs |
| 200 Hz | 3.9° | 0.27 µs |

**สามรอบที่เดาผิดติดกัน — Rf, R ไบแอส, แล้วถึงจะเจอหัวรับ** สองรอบแรกเป็นการอนุมาน
ย้อนกลับจากตัวเลขเดียว รอบที่สามเป็นการวัดตัวแปรนั้นตรงๆ ด้วยการกวาดความถี่
บทเรียนคือ เมื่อสมมติฐานเริ่มซับซ้อนขึ้นเรื่อยๆ ให้หยุดอนุมานแล้วไปวัดของจริง

**ยังเทียบเวลาสองช่องไม่ได้** เฟิร์มแวร์อ่านทีละช่อง เวลาที่ต่างกัน 93 µs อยู่ในพิสัย
ความไม่แน่นอนของทริกเกอร์ (±256 µs) ต้องรอเฟิร์มแวร์สองช่องพร้อมกันของ Stage 2

### 8.12 Stage 2 — เฟิร์มแวร์สองช่อง และการวัด Delta-t ครั้งแรก

ขยาย `esp32_scope` ให้อ่านสองช่องพร้อมกัน (`c 34,35`) แทนการเขียนสเก็ตช์ใหม่
เครื่องมือเดิมทุกตัวจึงยังใช้ได้ ผลที่ได้เปิดโปงพฤติกรรมของชิปที่ไม่มีในเอกสาร

**ADC เขียนค่าเดิมซ้ำ เมื่อสั่งเร็วเกินกว่าที่มันแปลงได้**

ดัมพ์คำดิบพร้อมแท็กช่อง (`x`) เห็นชัดว่าที่ 1 MHz ทุกค่าถูกเขียนออกมาสี่ครั้ง
เหมือนกันบิตต่อบิต ที่ 500 kHz สองครั้ง ค่าซ้ำพวกนี้ไม่ใช่ตัวอย่างเพิ่ม

| สั่ง | ซ้ำ | แปลงจริง |
|---|---|---|
| 250 kHz | 1 | 250 kHz |
| 500 kHz | 2 | 250 kHz |
| 1 MHz | 4 | 250 kHz |
| **800 kHz (2 ช่อง)** | **1** | **266 kHz ต่อช่อง** |

**ผลที่วัดมาก่อนหน้านี้ไม่ผิด** การเขียนค่าซ้ำคือ zero-order hold ซึ่งทำให้รูปคลื่น
เป็นขั้นบันได แต่**ไม่เลื่อนแกนเวลา** ระยะและความถี่ที่รายงานไว้ทั้งหมดยังถูกต้อง
สิ่งที่เสียไปคือความละเอียดเชิงเวลา และ `#FRAME` ตอนนี้รายงาน `skew_us` ที่
**วัดจากเวลาจริง** แทนที่จะคำนวณจากอัตราที่สั่ง เพราะชิปไม่ได้ให้ตามที่สั่งเสมอ

ตัวถอดช่องจึงต้องนับ**การเปลี่ยนแท็กช่อง** ไม่ใช่นับคำที่มาถึง และต้องล็อกกับ
ช่องแรกของแพตเทิร์นก่อนเก็บ ไม่งั้นเฟรมที่ DMA ส่งมากลางแพตเทิร์นจะสลับหัวรับ
สองตัวกัน = กลับเครื่องหมายของมุมแบบสุ่ม ซึ่งแย่กว่าพังไปเลย

**ผลวัด Delta-t ครั้งแรก** (`tools/tdoa.py` · 25 ช็อต · 266 kS/s/ช่อง · SNR 44 dB)

| | ค่า |
|---|---|
| Delta-t (เฟส) | 50.4 µs |
| σ ทั้งชุด | 2.52 µs |
| σ ระหว่างช็อตติดกัน | 1.38 µs |
| กระโดดข้ามคาบ | **0 จาก 25** |

**ศูนย์ cycle slip** คือสิ่งที่ต้นแบบ Nano ทำไม่ได้ตลอดทั้งโปรเจกต์ (มี 6 กลุ่ม
ห่างกันกลุ่มละ 25 µs) วิธีสองชั้น - เอนเวโลปหาคาบ เฟสหาตำแหน่งในคาบ - ได้ผล

**ยังไม่ผ่าน 1 µs แต่ตัวจำกัดไม่ใช่วงจร** หลักฐานสามข้อ

1. ค่ามีสหสัมพันธ์กับช็อตถัดไป **0.70** เสียงรบกวนขาวต้องได้ ~0 นี่คือการเลื่อนไหล
2. ระยะที่อ่านได้แกว่ง **10.3 mm** ตลอด 25 ช็อต Delta-t แกว่งตามกันเป็นล็อกสเต็ป
3. ที่ SNR 44 dB เสียงรบกวนความร้อนให้ σ ได้แค่ **0.025 µs** เล็กกว่าที่วัดได้ 100 เท่า

Delta-t ที่แกว่ง 9.1 µs = เป้าขยับข้าง **4.1 mm** ที่ระยะ 32 cm ซึ่งเป็นขนาดที่แผ่น
สะท้อนที่ไม่มีที่ยึดขยับได้สบายๆ **ต้องทำที่ยึดแผ่นสะท้อนก่อนจึงจะวัด σ ได้จริง**

### 8.13 Stage 2 ผ่านเกณฑ์แรก — sigma(Delta-t) = 0.37 us

ยึดแผ่นสะท้อนแล้ววัดใหม่ ผลเปลี่ยนทันที: 26 ใน 30 ช็อตกระจุกอยู่ที่ 7.3-9.1 us
ส่วนอีก 4 ช็อตไปอยู่ที่ -16 us **ห่างกันพอดีหนึ่งคาบพาหะ** การเลื่อนไหลที่เคยเห็น
หายไปหมด เหลือปัญหาเดียวคือ cycle slip

**ที่ยึดแผ่นแก้ปัญหาที่ใหญ่ที่สุดจริง** — สหสัมพันธ์กับช็อตถัดไปหายไป และการแกว่ง
ของระยะที่อ่านได้ยุบลง

**สาเหตุของ cycle slip อยู่ที่ตัวหาค่าหยาบ** เดิมเอาเอนเวโลปของ *สัญญาณ* สองเส้น
มาสหสัมพันธ์กัน ซึ่งแกว่ง sigma 4.5 us เพราะหัวรับสองตัวเรโซแนนซ์ห่างกัน 874 Hz
หางจึงลากไม่เท่ากัน พอค่าหยาบพลาดเกินครึ่งคาบ (12 us) ชั้นละเอียดก็เกาะคาบข้างเคียง
เปลี่ยนมาใช้เอนเวโลปของ **ตัวสหสัมพันธ์** แทน ซึ่งยุบพลังงานทั้งพัลส์มาเป็นยอดเดียว
ความไม่เหมือนกันของหางจึงเฉลี่ยหายแทนที่จะสะสม

**แต่การแก้นั้นยังไม่พอ และเกือบหลอกเราสำเร็จ** ที่หน้าต่าง 600 us ได้ sigma 0.38 us
กับ 0 slip ซึ่งดูเหมือนผ่านสวยงาม — แต่มันเกาะผิดคาบทั้ง 30 ช็อต ค่ากลางอยู่ที่
-16 us แทนที่จะเป็น +7 us

| หน้าต่าง | ค่าหยาบ sigma | ค่ากลาง (ละเอียด) | sigma |
|---|---|---|---|
| 400 us | 13.15 us | -16.47 us | 12.41 us |
| 600 us | - | **-16.10 us (ผิดคาบ)** | **0.38 us** |
| 1000 us | 9.26 us | -16.84 us | 11.70 us |
| **1600 us** | **1.87 us** | **+7.41 us** | **0.37 us** |
| 2400 us | 1.88 us | +6.92 us | 0.37 us |

> **sigma ต่ำไม่ได้แปลว่าถูก** ชุดที่ผิดทั้งชุดก็มี sigma ต่ำได้ สิ่งที่แยกถูกออกจากผิด
> คือการที่คำตอบ**ลู่เข้าหาค่าเดิมเมื่อเปลี่ยนพารามิเตอร์** 1600 กับ 2400 us ให้
> +7.41 และ +6.92 us ตรงกัน และตรงกับกลุ่มใหญ่ของอัลกอริทึมตัวเก่าด้วย

หน้าต่างที่ยาวขึ้นทำให้ค่าหยาบแม่นขึ้นเจ็ดเท่า (sigma 13.15 -> 1.87 us) เพราะจับ
พลังงานของพัลส์ได้ครบ ค่าตั้งต้นของ `tools/tdoa.py` จึงเป็น 1600 us

**ผลสุดท้าย 30 ช็อต ที่ 266 kS/s ต่อช่อง SNR 44 dB**

| | ค่า | เกณฑ์ |
|---|---|---|
| Delta-t | +7.41 us | - |
| **sigma(Delta-t)** | **0.37 us** | **< 1.00 us ผ่าน** |
| cycle slip | **0 จาก 30** | - |
| ความละเอียดเชิงมุมที่ได้ | 0.030 deg | - |

เทียบกับต้นแบบ Nano ที่กระโดดเป็นก้อนละ 25 us หกกลุ่ม ตอนนี้เหลือกลุ่มเดียว
กว้าง 0.37 us **นี่คือจุดที่โปรเจกต์เปลี่ยนจาก pseudo-TDOA เป็น TDOA จริง**

**ยังเหลือในเกณฑ์ Stage 2** ค่าสัมบูรณ์ยังมีออฟเซ็ตของสองช่องปนอยู่ ต้องคาลิเบรต
ด้วยเป้าที่อยู่ตรงหน้าพอดี (Delta-t เชิงเรขาคณิต = 0) แล้วจึงทดสอบซ้าย/กลาง/ขวา
เทียบกับไม้โปรแทรกเตอร์ให้ได้ +-3 deg

### 8.14 คาลิเบรตออฟเซ็ตของสองช่อง — และเหตุผลที่ต้องเลือกคาบจากทั้งชุด

**เป้าที่ลองแล้วไม่ผ่าน** ก่อนจะกลับมาที่แผ่นเรียบ ลองสองอย่างและได้ตัวเลขที่สอนอะไรเยอะ

| เป้า | แอมป์ | SNR | slip | sigma |
|---|---|---|---|---|
| แผ่นเรียบ ~42 cm | 199 mV | 41 dB | 0/30 | **0.38 us** |
| กระดานที่ 69 cm | 165 mV | 39 dB | 5/20 | 12.25 us |
| กระป๋อง d66 ~30 cm | 27 mV | 23.5 dB | 9/20 | 20.14 us |

**กระป๋องอ่อนเกินไป** หน้าตัดสะท้อนกลับของทรงกระบอกน้อยกว่าแผ่นเรียบ 160 เท่าในเชิงกำลัง
ทฤษฎีทำนายว่า 262 mV จะเหลือ 21 mV วัดได้ 18-26 mV ตรงกัน - เป็นการยืนยันสูตร
แต่ก็เป็นการยืนยันว่าคำแนะนำ "ใช้ทรงกระบอกเพราะไม่ต้องเล็ง" นั้นลืมดูงบสัญญาณ

**กระดานที่ 69 cm แรงพอแต่ยังพัง** เพราะมัน**แผ่ยาวในแนวระยะ** 64-80 cm = 930 us
เป้าที่แผ่ยาวทำให้ยอดสหสัมพันธ์กว้าง ค่าหยาบจึงแกว่ง 11 us ชนขอบครึ่งคาบพอดี
**SNR สูงอย่างเดียวไม่พอ เป้าต้องกระชับในแนวระยะด้วย**

จึงเพิ่ม `--gate-cm` เข้า `tools/tdoa.py` เป็นการถาวร ยอดที่แรงที่สุดในบันทึกไม่ใช่เป้าเสมอไป

**ปัญหาที่แท้จริงของ cycle slip: เอนเวโลปกับเฟสวัดคนละอย่าง**

พอกลับมาใช้แผ่นเรียบ SNR 41 dB แต่ยัง slip 11 จาก 30 ค่าหยาบอยู่ที่ 9.4 us
ส่วนค่าละเอียดอยู่ที่ -1.4 กับ +23 us **ค่าหยาบตกกลางระหว่างสองคาบพอดี** จึงโยนเหรียญ

ต้นเหตุคือหัวรับสองตัวที่ f0 ห่างกัน 874 Hz ที่ Q ~20 ยิงที่ 40 kHz

| | ช่อง 1 | ช่อง 2 | ต่างกัน |
|---|---|---|---|
| หน่วงเอนเวโลป (group) | 61.3 us | 29.5 us | **-31.9 us** |
| หน่วงเฟส | 3.54 us | 4.43 us | 0.89 us |

ก่อนหน้านี้เคยสรุปว่า 874 Hz เป็น "แค่ออฟเซ็ตคงที่ calibrate ออกได้" - **จริงสำหรับเฟส
แต่พลาดว่ามันพังการส่งต่อระหว่างชั้นหยาบกับชั้นละเอียด** เพราะ 32 us มากกว่าครึ่งคาบ 12.5 us
วัดจริงได้ 7.5-10.8 us (Q จริงต่ำกว่าที่สมมติ) ซึ่งก็ยังกินขอบเกือบหมด

**ทางแก้: เลือกคาบจากทั้งชุด ไม่ใช่ทีละช็อต** เป้าไม่ขยับระหว่างชุดวัด ทุกช็อตจึงต้อง
ตอบค่าเดียวกัน `resolve()` เริ่มจากค่าหยาบเป็นจุดตั้งต้นแล้ววนให้ทุกช็อตเกาะค่ากลางร่วมกัน
ผลคือ slip 11/30 -> **0/30** และ sigma 11.97 -> **0.38 us**

> ข้อจำกัดที่ต้องรู้: ใช้ได้เมื่อเป้านิ่งกว่าครึ่งคาบ (12.5 us = 7 mm ที่ 42 cm) ตลอดชุด
> ตอนกวาดมุมต้องแยกชุดวัดต่อหนึ่งตำแหน่ง ห้ามขยับกลางชุด

**ตรวจการลู่เข้าก่อนเชื่อ** (บทเรียนจาก 8.13 - sigma ต่ำไม่ได้แปลว่าถูก)

แยกสองอย่างนี้ออกจากกันไม่ได้ที่ระดับนี้ และไม่จำเป็นต้องแยก เพราะเกณฑ์คือ +-3 deg

### 8.16 Stage 2 ปิดจบ (ส่วนอิเล็กทรอนิกส์) — และเพดานของการวัดด้วยมือ

หลังคาลิเบรตศูนย์ ทดลองกวาดมุมด้วยการเลื่อนเป้า เจอว่าทุกความคลาดสืบกลับไปที่
**การวางเป้าด้วยมือ ไม่ใช่เซ็นเซอร์**

**บทเรียนใหญ่ที่สุดของ Stage 2: เป้าที่ต้องเล็งวัดมุมไม่ได้** แผ่นเรียบ/โค้งสะท้อนแบบ
กระจก จุดสะท้อนอยู่ที่มุมตกกระทบ = มุมสะท้อน พอเลื่อนแผ่นแล้วเอียงเล็งใหม่ เรากำหนด
จุดสะท้อนเองด้วยการเอียง การเลื่อนจึงไม่มีผล พิสูจน์ด้วยการแก้ย้อน: เลื่อนแผ่นซ้าย 100 mm
จุดสะท้อนจริงขยับแค่ 3 mm ส่วนเลื่อนขวา 100 mm จุดสะท้อนไป 85 mm - ไม่สมมาตรเพราะ
มันตามการเล็ง ทางแก้คือทรงกระบอกตั้งซึ่งสะท้อนรอบตัวจากแกน ไม่ต้องเล็ง เลื่อนแล้ว
จุดสะท้อนไปตามจริง

**แต่ถึงใช้ทรงกระบอก การวางด้วยมือบนโต๊ะก็ยังคลาด** เลื่อน "ขวา 100 mm" ระบบอ่านได้
ว่าข้าง 66 mm + ถอย 30 mm เพราะแกนโต๊ะไม่ตั้งฉากแนวมองพอดี ความคลาดนี้ ~2-3°
เทียบเท่างบทั้งงบ

| | ความแม่น |
|---|---|
| เซ็นเซอร์ (พิสูจน์ซ้ำ 5+ ครั้ง) | 0.05° (sigma 0.4-0.6 us) |
| วางเป้าด้วยมือ + ไม้บรรทัด | ~2-3° |

**เกณฑ์ที่ผ่านชัด** sigma(Delta-t) < 1 us (ได้ 0.36-0.63), ไม่มี cycle slip (0/20-0/30),
ทิศของมุมถูกเสมอ, ขนาดสมเหตุผล **ส่วนอิเล็กทรอนิกส์และอัลกอริทึม TDOA เสร็จสมบูรณ์**

**เกณฑ์ที่เลื่อนไปพิสูจน์ทีหลัง** ความแม่นมุมสัมบูรณ์ ±3° เทียบไม้โปรแทรกเตอร์ ติดที่
การวางเป้าด้วยมือ ไม่ใช่เซ็นเซอร์ - ควรพิสูจน์ด้วยกล้อง Astra (ground truth ระดับ mm)
ซึ่งเป็นเหตุผลที่แผนมีกล้องอยู่แต่แรก ไม่ใช่ด้วยไม้บรรทัด

พัลส์ตรงใช้เป็นศูนย์ไม่ได้ - อ่อนเกิน (SNR 14 dB) และปนเสียงที่เดินผ่านเนื้อ PLA
(เร็วกว่าอากาศ 6 เท่า เส้นทางในแขนสองข้างไม่เท่ากัน) ได้ 67 us แทนที่จะเป็น ~0

### 8.17 Stage 3 — ADC หลายช่องบน ESP32 ยุบแรงมาก แผนเดิมใช้ไม่ได้

ก่อนสร้างฮาร์ดแวร์ 6 ช่อง วัดอัตราแปลงจริงที่ตั้งได้หลายช่อง (ขาไม่ต่อก็สุ่มได้)

| ช่อง | อัตราแปลงรวมจริง | ต่อช่อง | ตัวอย่าง/คาบ 40 kHz |
|---|---|---|---|
| 1 | 1988 kHz | 1988 kHz | 49.7 |
| 2 | 533 kHz | 266 kHz | 6.66 |
| 3 | 267 kHz | 89 kHz | 2.22 |
| 4 | 267 kHz | 67 kHz | 1.67 |
| **6** | **267 kHz** | **44 kHz** | **1.11** |

**อัตรารวมยุบจาก ~2 MHz (1 ช่อง) เหลือ ~267 kHz (ตั้งแต่ 3 ช่อง)** เป็นข้อจำกัดของ
`adc_continuous` บน ESP32 - overhead ของการสลับแพตเทิร์นหลายช่องกินอัตราจนหมด
แผนเดิมเขียนว่า "2 MS/s / 6 = 333 kS/s/ช่อง" ซึ่งอิงอัตราที่สั่ง ไม่ใช่ที่ได้จริง
ที่ 6 ช่องได้แค่ 1.1 ตัวอย่างต่อคาบ วิธีเฟสต้องการ 6+ **สถาปัตยกรรม "6 ช่อง raw
บน ESP32 ตัวเดียว" เป็นไปไม่ได้**

ทางเลือกที่เหลือ (รอผู้ใช้ตัดสิน):

1. **จับคู่ตามลำดับ** อ้างอิง ch0 + หมุนช่องที่สอง ยิงเบิร์สต์ซ้ำต่อคู่ ได้ 266 kHz/ช่อง
   ที่พิสูจน์แล้ว 6 ช่อง = 5 คู่ x 25 ms = 125 ms/เฟรม (8 fps) · 9 ช่อง = 200 ms (5 fps)
   ต้องการฉากนิ่งช่วง 125-200 ms - ดีสำหรับเก็บ dataset วัตถุนิ่ง แต่วัตถุเคลื่อนที่จะเบลอ
2. **หลาย ESP32** 2 ช่อง/ตัว ที่ 266 kHz พร้อมกัน ซิงก์ด้วยสาย TX ร่วม มี ESP32 2 ตัว
   = 4 ช่องพร้อมกัน ครบ 6-9 ต้องซื้อเพิ่ม
3. **ADC ภายนอกแบบ simultaneous-sampling** เปลี่ยนฮาร์ดแวร์เยอะ

การจับคู่ตามลำดับ (ข้อ 1) ใช้ไปป์ไลน์ 2 ช่องที่พิสูจน์แล้วซ้ำได้เลย และเหมาะกับ
งานเก็บ dataset ที่ฉากนิ่ง จึงน่าจะเป็นก้าวแรกที่คุ้มที่สุดก่อนตัดสินใจซื้อ ESP32 เพิ่ม

### 8.18 Stage B — 4 ช่องทำงาน และ "มุม" เรียนได้เป็นครั้งแรก

จาก §8.17 เลือกทางที่ 1 (**จับคู่ตามลำดับ**) — ต่อ RX 4 ตัวเข้า ESP32 ตัวเดียว แล้วยิงสองครั้ง
อ่านทีละคู่ ได้ 266 kHz/ช่องที่พิสูจน์แล้ว โดยไม่ต้องซื้อ ESP32 เพิ่ม ใช้ได้เพราะฉากนิ่งตอนเก็บ
dataset (master/slave อ่านพร้อมกันจริง เลื่อนไปตอนรถวิ่ง)

| คู่ | หัวรับ | GPIO | เบสไลน์ |
|---|---|---|---|
| 1 | A140 / C140 | 35 / 34 | **242 mm** |
| 2 | A80 / C80 | 32 / 33 | **139 mm** |

ช่อง 3-4 ต่อบน MCP6004 ตัวที่สอง บนบอร์ดทดลองอีกแผ่น **ยืมไฟ 3.3V, GND และ VREF
(ที่บัฟเฟอร์แล้ว) ข้ามมาจากบอร์ดเดิม** ไม่ทำตัวแบ่ง VREF ใหม่ — ดู `hardware/rx_frontend.md` §4.2

#### ช่องหนึ่งอ่อนกว่าเพื่อน 3 เท่า — และวิธีไล่หาที่ชี้ตัวการได้จริง

วัดด้วย `collect.py --track` (อ่านระยะ+ความแรงเอคโค่สดทุกช่อง) เจอ g34 ให้ amp 17 ขณะที่
g35 ให้ 50 กับเป้าตัวเดียวกัน **แต่ระยะอ่านถูก (85 vs 82 cm) = สายไม่ขาด**

ไล่ผิดสองรอบก่อนเจอ: เดาว่าเป็นหัวรับ (เรโซแนนซ์ต่างกัน 874 Hz ตาม §8.11) —
**ลองเปลี่ยนหัว 3 ตัว amp ค้างที่ 17 เท่าเดิมทุกตัว** ถ้าเป็นหัวจริง amp ต้องเปลี่ยนตามหัว
จึงตัดออกได้ว่าเป็นวงจร

วิธีที่ชี้ตัวการได้ คือ **ฉีดสัญญาณรู้ค่าแล้ววัดทีละสเตจ** (ESP32 เป็นทั้งเครื่องกำเนิดและสโคป):

```
GPIO26 (DAC, คำสั่ง d 40000) --[100k]--+--> อินพุตช่อง g34   (ถอดหัวรับออกก่อน)
                                       |
                                     [1k]
                                       |
                                      GND          หัววัด = GPIO36 (ขา SP)
```

```bash
python tools/scope_view.py --port COM5 --probe 36 --tone 40000 --no-fire
```

| จุดวัด | ได้จริง | ควรได้ | สรุป |
|---|---|---|---|
| ขา 1 (ออกสเตจ 1) | 116 mVpp | ~116 | ✅ เกน ×11 ปกติ |
| ขา 7 (ออกสเตจ 2) | 262 mVpp | ~1270 | ❌ **เกน ×2.3 ควรเป็น ×11** |

ตัวการคือ **Rf2 เสียบผิดรู** แก้แล้วขา 7 ได้ 1271 mVpp และ **g34 amp 17 → 81**

> **บทเรียน**: อาการ "ช่องอ่อน" มีผู้ต้องสงสัยสามราย (หัวรับ / วงจร / สาย) การเดาแล้วเปลี่ยน
> ของเสียเวลาและเคยพาไปผิดทางสองรอบ **การฉีดสัญญาณที่รู้ค่าแล้ววัดทีละสเตจ ตัดผู้ต้องสงสัย
> ได้ทีละราย** และบอกตำแหน่งที่เกนหายได้ตรงๆ — เพิ่ม `--tone`/`--no-fire` ใน `scope_view.py`
> ไว้ทำซ้ำได้

#### สภาพแวดล้อมการวัด — สองเรื่องที่เปลี่ยนผลมากกว่าวงจร

1. **พื้นกระเบื้องคือกระจกสะท้อน 40 kHz** วางอาเรย์บนพื้นแล้วยิงเฉียดพื้น เอคโค่เป้าจมกับ
   เสียงเด้งพื้น (ยอดที่แรงสุดกระโดดมั่ว SD 34-50 cm ไม่ตามเป้าเลย) → **ยกอาเรย์และเป้า
   พ้นพื้น ~50 cm**
2. **เป้าแบนต้องเล็งทุกครั้ง เป้ากลมไม่ต้อง** ผิวเรียบสะท้อนแบบกระจก (มุมตกกระทบ =
   มุมสะท้อน) เลื่อนไปข้างแล้วไม่หันหน้าเข้าอาเรย์ = เสียงเด้งหลุด ไม่กลับมา ส่วน**ทรงกระบอก
   ตั้ง (ท่อ PVC) สะท้อนกลับได้จากทุกมุมแนวนอน** เลื่อนไปตำแหน่งไหนก็ผลักตรงๆ ได้ ไม่ต้องเล็ง

#### มุมเรียนได้ — และเบสไลน์ยาวคือตัวทำงาน

เก็บ dataset กวาดมุมด้วยท่อ PVC แล้วเทรน (แบ่ง train/val ตามฉาก คนละรอบเก็บ):

| ชุด | เบสไลน์ที่ใช้ | มุม MAE | เทียบ baseline |
|---|---|---|---|
| 2 ช่อง (ang80a/b) | 139 mm | 9.4° | **ชนะ 30%** |
| 4 ช่อง (ang4_a/b) | 139 + 242 mm | **7.3°** | **ชนะ 51%** |

ยืนยันว่าเป็นฟิสิกส์จริง ไม่ใช่บังเอิญ — TDOA เทียบมุมจากกล้อง:

| มุมกล้อง | −26° | −13° | **0°** | +13° | +26° |
|---|---|---|---|---|---|
| lag เบสไลน์ 242 mm | −129 µs | −175 µs | **−14 µs** | +63 µs | +206 µs |

กลาง ≈ 0 · ซ้ายลบ ขวาบวก · โตตามมุม **corr(มุม, TDOA) = +0.64 สำหรับ 242 mm แต่
−0.09 สำหรับ 139 mm** และ corr(มุม, อัตราส่วนแอมป์) = 0.02 → **มุมมาจากเวลาล้วน ไม่ใช่ความแรง**

> **เบสไลน์ยาวชนะขาด และไม่มีข้อเสียที่กลัวไว้** แผนเดิมคิดว่าต้องมีเบสไลน์สั้นมาแก้ความ
> กำกวมข้ามคาบ (coarse-to-fine) **แต่เราหา TDOA จากเอนเวโลป ไม่ใช่เฟสพาหะ จึงไม่มีคาบ
> ให้กำกวมตั้งแต่แรก** เบสไลน์ยาวให้ lag ต่อองศาใหญ่กว่า (±206 vs ±80 µs) = SNR เชิงมุมดีกว่าล้วน
> เบสไลน์สั้นจะมีประโยชน์ก็ต่อเมื่อเปลี่ยนไปใช้เฟสพาหะเพื่อความละเอียดระดับ sub-µs

#### T0 ผิดไป 785 µs — ตัวแก้ที่ให้ผลมากที่สุดของ "ระยะ"

เทียบระยะที่ US อ่านได้กับกล้อง 454 ตัวอย่าง 3 ระยะ พบ **bias คงที่ +13 cm ทุกระยะ**
(ไม่ใช่การกระจาย — เป็นค่าคงที่) แปลว่าเวลาศูนย์ที่ใช้อยู่ (435 µs) น้อยไป

| T0 | ตรงกับกล้อง ±20 cm | MAE |
|---|---|---|
| 435 µs (เดิม) | 78% | 20.0 cm |
| **1220 µs (คาลิเบรตแล้ว)** | **93%** | **9.7 cm** |

1220 µs = เวลาเบิร์สต์ (16 รอบ = 400 µs) + หน่วงเอนเวโลป/ฟิลเตอร์ + ออฟเซ็ตทริกเกอร์
**แยกวัดทีละส่วนยาก แต่คาลิเบรตกับ ground truth ได้ตรงๆ ในขั้นตอนเดียว**

เพิ่ม **range gate 40-250 cm** ตอนหายอดเอคโค่ด้วย — เพราะบางเฟรม argmax ไปเกาะเสียง
สะท้อนใกล้ (เคยอ่านได้ 26 cm ทั้งที่เป้าอยู่ 130 cm) **และมันทำให้มุมพังไปด้วย** เพราะ
หน้าต่างหา TDOA อิงตำแหน่งยอดนี้ ยอดผิด = หน้าต่างผิด

#### ข้อสรุปเชิงออกแบบ: ระยะคำนวณ มุมเรียน

| | ฟิสิกส์ตรงๆ | โมเดลที่เทรน |
|---|---|---|
| **ระยะ** | **9.7 cm** | 16.7 cm |
| **มุม** | (ต้องรวมหลายช่อง) | **7.3°** |

ระยะมาจากเวลาเอคโค่ตรงๆ คาลิเบรตครั้งเดียวจบ — เทรนแล้วแย่กว่าเพราะต้องเดาข้ามระยะ
ที่ไม่เคยเห็น **ML จึงควรมีไว้ทำสิ่งที่คำนวณตรงๆ ไม่ได้ คือมุมและการแยกวัตถุ**

บทเรียนโมเดลที่แลกมาด้วยผลติดลบ: feature 518 มิติ (เอนเวโลปเต็ม 128 จุด × 4 ช่อง)
ทำให้ทำนายแย่กว่าเดาค่าเฉลี่ย **−134%** แก้ด้วย **แยก feature ตามเป้า** (ระยะใช้เวลาเอคโค่
8 มิติ · มุมใช้ TDOA 6 มิติ) เพราะปนกันแล้วต่างฝ่ายกลายเป็น noise ของอีกฝ่าย
