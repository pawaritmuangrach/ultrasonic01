## ใช้ยังไง

**1. เช็คเซ็นเซอร์** (ไม่เขียนไฟล์):

```bash
python car/collect.py --check --pins 34,35,32,33
```

**2. เช็คว่าวัตถุเป็นเสียงเด่น** (สำคัญ — us range ต้องตรงกับกล้อง ไม่งั้นไปล็อกผนัง):

```bash
python car/collect.py --track --pins 34,35,32,33
```

ต้องขึ้น "ตรง ✓" ถ้า "ผิด ✗ ล็อกฉากหลัง" ให้เล็งอาเรย์ไปที่โล่ง วัตถุหน้าแบนหันเข้า

**3. เก็บ** (โหมด `--shots` ไม่มีหน้าต่าง กันปัญหา GUI ทั้งหมด):

```bash
python car/collect.py --scene c4_d80 --pins 34,35,32,33 --shots 40
```

- `--shots N` เก็บ N ตัวอย่างแล้วออก · `--period 2` วินาทีต่อภาพ (ให้เวลากวาดวัตถุ)
- จอบอก "กวาดไป: ซ้าย/กลาง/ขวา" — เริ่มกล่องซ้ายสุด เลื่อนไปขวาให้พอดีหมดเวลา
- **ภาพสีปิดโดยปริยาย** (DSHOW มักค้าง เราใช้ depth เป็น label) เติม `--rgb` ถ้าอยากได้

**ถ้าต้องเดินไปขยับวัตถุเอง — ใช้ `--auto-still` (แนะนำ เก็บชุดใหญ่)** ไม่ต้องกดปุ่มเลย:

```bash
python car/collect.py --scene d90 --pins 34,35,32,33 --auto-still --expect-cm 90 --min-valid 0.1
```

ไหลงาน: **ขยับวัตถุ → เดินออกจากเฟรม → ยืนนิ่ง 1-2 วิ → มันเก็บเอง → ขยับต่อ** วนไปเรื่อยๆ
(Ctrl-C หยุด · ใส่ `--shots N` ให้หยุดเองเมื่อครบ)

- ตรวจ "ฉากนิ่งหลังมีการขยับ" จาก depth — จึงไม่เก็บตอนคุณยังอยู่ในเฟรม และไม่เก็บ
  ตำแหน่งเดิมซ้ำ (ต้องเห็นการขยับก่อนถึงเก็บรูปถัดไป)
- `--expect-cm 90` = รับเฉพาะเฟรมที่กล้องเห็นของใกล้สุดราว 90±30 cm — กันเฟรมที่ติดคน
  หรือกล้องไปล็อกฉากหลัง (`--tol-cm` ปรับความกว้างได้) · ในข้อมูลเก่ามีเฟรมแบบนี้ 7-9%

**ทุกครั้งที่เก็บ มันบอกตำแหน่งวัตถุ + ความครอบคลุม** เพื่อให้กวาดครบทุกทิศ ไม่กระจุกด้านเดียว:

```
  ✓ [23]   -19° ซ้าย     88cm   ซ้ายสุด:5 ซ้าย:6 กลาง:7 ขวา:3 ขวาสุด:2  ← ขาด ขวาสุด
  ✗ นอกระยะ: กล้องเห็น 197 cm (ซ้ายสุด) — ต้องการ 90±30 cm
```

- ตัวเลขหลังชื่อโซน = เก็บโซนนั้นไปกี่รูป · **`← ขาด` ชี้โซนที่ยังน้อยสุด ให้ย้ายท่อไปตรงนั้น**
- **ซ้าย/ขวาที่แสดง = มุมมองของคุณ (คนวางของ ยืนหน้ากล้อง)** ไม่ใช่มุมกล้อง — กลับด้านให้แล้ว
  เพราะยืนหน้ากล้องเห็นเป็นมิเรอร์ · โซน: ซ้ายสุด >18° · ซ้าย 7..18° · กลาง ±7° · ขวา -7..-18° · ขวาสุด <-18°
  (label ที่เทรนยังเป็นมุมกล้องจริง ไม่แตะ — กลับแค่ข้อความบนจอ)
- ขึ้น `✗ นอกระยะ` = กล้องไม่เห็นวัตถุที่ระยะที่ตั้งใจ (ไปล็อกฉากหลัง หรือคุณยังอยู่ในเฟรม)
  ไม่เก็บให้ ปรับตำแหน่งแล้วขยับใหม่

**หรือกดเองทีละรูปด้วย `--manual` (นิ่งสุด แนะนำถ้า auto-still ล้ม)**:

```bash
python car/collect.py --scene e80 --pins 34,35,32,33 --manual --expect-cm 80 --min-valid 0.1
```

ขยับวัตถุ → **เดินออกจากแนวเซนเซอร์ (ขาด้วย)** → กด ENTER (พิมพ์ q = ออก) · กด ENTER แล้ว
มันเช็คและบอกสถานะทันที:

```
  ✓ [12] ซ้ายสุด -26° 78cm   ซ้ายสุด:3 ซ้าย:2 กลาง:4 ขวา:1 ขวาสุด:2  ← ขาด ขวา
  ✗ นอกระยะ: ขวาสุด 45cm — ต้องการ 80±30 cm · ไม่เก็บ
  ✗ ติดขา/ของใกล้ 2 จุด (กลาง) — เดินออกให้พ้นแล้วกดใหม่
```

`--expect-cm 80` ทำให้เกิดสถานะ "นอกระยะ" (ถ้าไม่ใส่ จะบอกแค่โซน ไม่เช็คระยะ) · ทั้งสองโหมด
(manual/auto-still) จำเป็นเพราะ `--shots` อัตโนมัติตามเวลาจะจับ "ตัวคนเก็บ" = label เพี้ยน

> โหมดหน้าต่าง (SPACE เก็บ) ยังมี (`--scene X` เฉยๆ) แต่ **cv2 บน Windows ล้มบ่อย** (native crash)
> — แนะนำ `--manual` หรือ `--shots` แทน

**4. ตรวจก่อนเทรน · เทรน:**

```bash
python car/inspect_data.py --scene c4_d80
python car/train.py --scenes c4_d80 c4_d110 c4_d140
```

`train.py` แบ่ง val เป็นฉากระยะกลาง (interpolation ยุติธรรม) เมื่อมี ≥3 ระยะ

## กฎการเก็บที่ต้องจำ (บทเรียนสะสม)

1. **แบ่ง train/val ตามโฟลเดอร์ ไม่ใช่ตามเฟรม** เฟรมติดกันเกือบซ้ำ สุ่มแบ่งจะรั่ว
2. **จงใจสลับตำแหน่ง/ระยะ/ชนิดวัตถุ** ไม่งั้น NN เรียนทางลัด ("ซ้าย=ใกล้")
3. **หลายระยะ = หลายโฟลเดอร์** (d80/d110/d140) ไม่งั้นระยะไม่มีตัวแปรให้เรียน
4. **กวาดมุมให้ครบ ซ้าย-กลาง-ขวา** ในแต่ละระยะ (เคยพลาดเก็บแต่ซ้าย)
5. **วัตถุต้องเป็นเสียงเด่น** เช็ค `--track` ก่อน — อัลตราซาวด์เห็น "เสียงดังสุด" ไม่ใช่
   "ใกล้สุด" ผนังเรียบไกลดังกว่ากล่องเล็กใกล้ ต้องเก็บในที่โล่ง วัตถุหน้าแบน
6. **อาเรย์กับกล้องยึดติดกันแน่น ไม่ขยับระหว่างเก็บทั้งฉาก** ไม่งั้น label เลื่อน
7. **วัตถุต้องเป็นของใกล้จุดเดียว — เดินออกให้พ้น (ขาด้วย!)** ถ้าขาคุณอยู่ในเฟรมที่ระยะ
   พอๆ กับท่อ กล้องจะเลเบล "ขา" แทน "ท่อ" · `--auto-still`/`--manual` เช็ค `near_object_count`
   แล้ว ข้ามเฟรมที่มีของใกล้ 2 จุด และ `train.py` ก็กรองซ้ำอีกชั้น

## บทเรียนฮาร์ดแวร์/ซอฟต์แวร์ที่เจอจริง

**หัวรับหลุด → ช่องดังขึ้น ไม่ใช่เงียบลง** อินพุตออปแอมป์ลอยกลายเป็นเสาอากาศ รับคลื่น
จากตัวส่งแล้วถูกขยาย เห็นเป็นพัลส์ใหญ่ตรงจังหวะยิง แต่ไม่มีเอคโค่ตาม แยกด้วยการเพิ่ม
ความยาวเบิร์สต์ (`b 16`→`b 32`): เสียงจริงแรงขึ้น ไฟฟ้าเหนี่ยวนำนิ่งสนิท · ป้องกันด้วย
strain relief ทุกสายหัวรับ

**อัลตราซาวด์ล็อกฉากหลัง** วัตถุอ่อน (ขวด/ถังโค้ง) แพ้ผนังเรียบไกล → เพิ่มโหมด `--track`

**ขาคนเก็บติดเฟรม = label กำกวม** ถ้าขาอยู่ที่ระยะพอๆ กับเป้า `--expect-cm` (กรองแค่ระยะ)
จับไม่ได้ · เจอ e60 ติด 32% d130 ติด 27% (แต่ d70/d100 ที่เดินออกสุดติดแค่ 1-2%) → เพิ่ม
`near_object_count` นับ 'ก้อนของใกล้ที่แยกกัน' >1 = ข้าม (ทั้งตอนเก็บและตอนเทรน)

**พื้นกระเบื้อง = กระจกสะท้อน 40kHz** วางอาเรย์บนพื้นแล้วยิงเฉียดพื้น เอคโค่เป้าจมกับเสียง
เด้งพื้น (เอคโค่แรงสุดกระโดดมั่ว ไม่ตามเป้า) → **ยกอาเรย์+เป้าพ้นพื้น ~50 cm** และใช้
**ท่อ/ทรงกระบอกตั้ง** เป็นเป้า (สะท้อนกลับทุกมุมแนวนอน ผลักตรงๆ ได้ ไม่ต้องเอียงหาเซนเซอร์
แบบแผ่นเรียบที่เด้งหลุดถ้าไม่ตั้งฉากเป๊ะ)

**ช่องอ่อน: แยก "หัว" กับ "วงจร" ด้วยการลองหัวหลายตัว** เจอช่อง g34 amp ต่ำกว่า g35 ~3 เท่า
ตอนแรกสรุปผิดว่าเป็นหัว/เรโซแนนซ์ (จาก swap test ที่ไม่สะอาด) พอ**ลองหัว 3 ตัว amp ค้าง 17
เท่าเดิมทั้งหมด = ไม่ใช่หัว เป็นวงจรช่องเกนต่ำ** (ถ้าเป็นหัว amp ต้องเปลี่ยนตามหัว) · **อย่าด่วน
โทษหัว ลองหัวหลายตัวก่อน** · ปิดเคส: **ยิงโทน 40kHz (GPIO26 DAC → ÷100 → อินพุต) แล้ววัดทีละ
สเตจด้วย GPIO36** — สเตจ1 ×11 ดี แต่สเตจ2 ×2.3 (ควร ×11) → **ตัวการคือ Rf2 เสียบผิดรู** g34 amp
17→81 · วิธีไล่วัดทีละสเตจนี้ชี้ตัวการได้แม่นกว่าเดา (ดู `tools/scope_view.py --tone --probe`)

**calibrate ซอฟต์แวร์แก้ SNR ไม่ได้** ไม่ว่าต้นเหตุเป็นหัวหรือวงจร การคูณ gain ชดเชยขยาย
noise ขึ้นเท่ากัน SNR เท่าเดิม เอคโค่ที่จมอยู่ก็ยังจม → ต้องแก้ฮาร์ดแวร์ที่ต้นเหตุจริง

**คาลิเบรต T0 กับกล้อง = ตัวแก้ที่ให้ผลมากที่สุดของระยะ** ค่าเดิม 435 µs ทำให้ US อ่านเกินจริง
**+13 cm ทุกระยะ** (bias คงที่ เห็นชัดเมื่อเทียบกับกล้อง 3 ระยะ) แก้เป็น **1220 µs** แล้ว US ตรงกับ
กล้องภายใน 20 cm จาก **78% → 93%** · MAE **20 → 9.7 cm** — ค่านี้คือเวลายิง (เบิร์สต์ 400 µs) +
หน่วงเอนเวโลป/ฟิลเตอร์ + ออฟเซ็ตทริกเกอร์ วัดเองยาก **แต่คาลิเบรตกับ ground truth ได้ตรงๆ**

**range gate ช่วย "มุม" ด้วย ไม่ใช่แค่ระยะ** บางเฟรม argmax ไปเกาะเสียงสะท้อนใกล้ (เคยอ่านได้
26 cm ทั้งที่เป้าอยู่ 130) พอยอดผิด **หน้าต่างหา TDOA ก็ผิดตาม = มุมพัง** จำกัดช่วงค้นหาเป็น
40-250 cm แล้วทั้งระยะและมุมดีขึ้น (18% / 16%)

**ฟิสิกส์ตรงๆ แม่นกว่าโมเดลสำหรับ "ระยะ"** (9.7 cm เทียบโมเดล 16.7 cm ตอนข้ามระยะ) →
ระยะควรคำนวณจากเวลาเอคโค่ ไม่ใช่เรียน · **มุมคือเป้าหมายจริงของ ML** (ต้องรวมหลายช่อง)

**แยก feature ตามเป้า** ระยะใช้เวลาเอคโค่ (8 มิติ) · มุมใช้ TDOA (6 มิติ) — เดิมรวมกัน 518 มิติ
overfit หนัก (−134%) เพราะ envelope เต็มเป็น noise ของมุม และ direction feature กวนระยะ

**`--track` แครช native ตอนอ่านกล้องสด** live `cam.read()` ในลูปเร็วๆ ล้มระดับ native
(try/except Python จับไม่ได้ เด้งกลับ prompt เงียบ) → track ตัดกล้องออก ใช้ US อย่างเดียว
เทียบระยะกับที่วางเป้าจริงเอา (คนรู้อยู่แล้วว่าวางกี่ cm)

**สายจั๊มยาวไม่กระทบ Δt** สัญญาณไฟฟ้าช้าลง ~1 ns/20cm เทียบ Δt เสียงเป็น µs = 1000 เท่า

**กล้องสี DSHOW ค้าง/หลุดเงียบ** → ปิดภาพสีโดยปริยาย ใช้แค่ depth (ซึ่งเป็น label จริง)

**OpenMP ซ้อนกัน (cv2+numpy+OpenNI) crash เงียบบน Windows** → ตั้ง `KMP_DUPLICATE_LIB_OK=TRUE`
ที่หัวไฟล์ก่อน import

**การ import โมดูลกลางคันขณะ OpenNI ทำงาน = ล้ม native** อาการ: กด ENTER แล้วโปรแกรมปิดเอง
· **`faulthandler.enable()` ชี้จุดตายได้ทันที** (ใส่ไว้ที่หัว `collect.py` แล้ว) เจอสองรอบ
คนละโมดูล: `np.percentile` ลาก **`numpy.ma`** มา · `np.savez_compressed` ลาก **`zipfile`** มา
ทั้งคู่ตายที่ `_compile_bytecode` (heap พัง `0xc0000374`)

**ไล่ปิดทีละโมดูลไม่จบ → ใช้ `_warmup()` แทน**: ซ้อมรันเส้นทางจริง (save_sample +
scene_position + near_object_count) ด้วยข้อมูลปลอมหนึ่งรอบ **ก่อนเปิดกล้อง** เพื่อให้ lazy
import ทุกตัวเกิดตอนที่ยังปลอดภัย · วัดแล้วดึงมา 22 โมดูล (zipfile, lzma, bz2, tempfile,
shutil, threading, ...) และหลังจากนั้น **เส้นทางเก็บจริงไม่โหลดโมดูลใหม่อีกเลย** ตามด้วย
`gc.freeze()` ลดงาน GC · เสริมด้วย `labels._percentile5` ที่ใช้ `np.partition` แทน
`np.percentile` (ค่าตรงเป๊ะ — ยืนยันกับ label จริง 211 ช่อง ต่าง 0.0)

> **หลักที่ได้: โค้ดที่รันคู่กับไลบรารี native ต้องโหลดโมดูลให้ครบก่อนเริ่มงานจริง**
> อย่าเชื่อว่า import ครบแล้วเพราะ numpy/cv2 มี lazy import ซ่อนอยู่เยอะ — **ซ้อมรัน
> เส้นทางจริงหนึ่งรอบ** ชัวร์กว่าไล่เดาชื่อโมดูล

**Ctrl-C ระหว่างเก็บ = กล้องค้าง** ถ้าออกโดยไม่ปิดกล้อง รอบหน้าจะล้มเป็น `access violation`
ตอน `create_depth_stream` (ต้องถอด-เสียบสาย USB ถึงหาย) → `main()` ห่อด้วย `try/finally`
ปิด ESP32+กล้องเสมอ และ manual mode จับ `KeyboardInterrupt` แล้ว

**GUI ปุ่ม a/q ไม่ทำงานกับคีย์บอร์ดไทย** (keycode เพี้ยน) → ใช้โหมด `--shots` ไม่มีหน้าต่าง

## อัดต่อเนื่อง (record.py) — วิธีเก็บ dataset แบบใหม่

`collect.py` เก็บทีละช็อตตอนกดปุ่ม (ฉากต้องนิ่ง) · `record.py` **อัดไม่หยุด** คนเลื่อนวัตถุ
ไปมาได้ตลอด กล้อง depth เป็นเฉลยทุกเฟรม แบ่งเก็บเป็นช่วง ๆ เพื่อใช้แบ่ง train/test

```
python car/record.py --port COM5 --name rec       # 4 ช่วง ช่วงละ 5 นาที
python car/train_sections.py --name rec           # เทรน 3 ช่วง ทดสอบ 1 ช่วง
```

### ความเร็วจริง (วัด ส.ค. 2026 — อย่าเชื่อตัวเลขที่คาดเดา)

| ตั้งค่า | 921600 baud | **2 Mbaud (ตอนนี้)** |
|---|---|---|
| 4 ช่อง · 4000 ตัวอย่าง (258 cm) | 2.6 | **5.1** |
| 2 ช่อง · 4000 ตัวอย่าง | 5.2 | **10.3** |
| 4 ช่อง · 2600 ตัวอย่าง (168 cm) | 4.0 | ~7.8 |

**คอขวดคือเวลาส่งข้อมูล ไม่ใช่เซ็นเซอร์**: คลื่นดิบ 4000 ตัวอย่าง x 4 ช่อง x 2 ไบต์ = 16 KB
เฟรมส่งเป็นไบนารีอยู่แล้ว (ไม่ได้เสียกับข้อความ) จึงเหลือทางเดียวคือเพิ่มความเร็วสาย

**แก้แล้ว ส.ค. 2026: เปลี่ยน `Serial.begin` จาก 921600 เป็น 2000000** ในเฟิร์มแวร์
`esp32_scope.ino` และตั้ง `car/ultrasonic.py: BAUD` ให้ตรงกัน -> เร็วขึ้น ~2 เท่า
**โดยเฟรมเสีย 0 เฟรม** และข้อมูลเหมือนเดิมทุกอย่าง (ตรวจแล้ว: อัตราสุ่ม 266 kHz/ช่องเท่าเดิม,
skew 1.877 us เท่าเดิม, ค่าเฉลี่ยดิบ ~1890 counts เท่าเดิม — เทียบกับ npz ที่อัดก่อนเปลี่ยน)
ไฟล์เดิมสำรองไว้ที่ `esp32_array/esp32_scope/esp32_scope.ino.bak921600`

**สองค่านี้ต้องตรงกันเสมอ** ถ้าแฟลชเฟิร์มแวร์เก่ากลับ ต้องแก้ `BAUD` กลับด้วย ไม่งั้นอ่านไม่ออก
ถ้าเจอเฟรมเสียบ่อยให้ลดทั้งคู่เป็น 1500000

เร็วกว่านี้ต้องให้ ESP32 คำนวณเอนเวโลปเองแล้วส่งเฉพาะผลลัพธ์ (~200 จุดแทน 4000)
ซึ่งจะเสียคลื่นดิบไปวิเคราะห์ย้อนหลังไม่ได้ จึงยังไม่ทำ

**ดีเลย์ที่ตัดทิ้งได้ฟรี**: เดิมหน่วง 0.2 วิหลังสั่ง ADC สลับคู่ช่อง วัดที่ 0.20/0.08/0.03/0.00
ได้ 1.3/1.8/2.2/**2.6** fps โดย**เฟรมเสีย 0 ทุกค่า** -> ตั้ง `SWITCH_SETTLE = 0.0` แล้ว

### กล้อง depth
รองรับ **160x120 / 320x240 / 640x480 ที่ 30 fps** และ 1280x1024 ที่ 7 fps เท่านั้น
**ไม่มีโหมด 15 fps** — `--cam-fps 15` จึงเป็นการอ่าน 30 fps แล้วเก็บเว้นเฟรม
depth อ่านในเธรดแยกตลอดเวลา ทุกปิงจึงได้เฟรมสด ๆ (วัดจริง: เหลื่อมเวลาเฉลี่ย **33 ms**)

### ทำไมต้องแบ่ง train/test ตาม "ช่วง" ไม่ใช่สุ่มทีละเฟรม
เฟรมที่ติดกันในเวลาแทบเหมือนกันทุกอย่าง ถ้าสุ่มแบ่ง เฟรมข้างเคียงของเฟรมทดสอบจะไปอยู่ใน
ชุดเทรน = โมเดลเคยเห็นคำตอบมาแล้ว ตัวเลขจะสวยเกินจริง (เคยเจอมาแล้วตอน baseline 1.4 cm)

### เป้าที่ **เคลื่อนที่** (เช่นคนเดิน) — ต้องระวังเรื่องยิงสองรอบ

4 ช่องอ่านพร้อมกันไม่ได้ ต้องยิงสองรอบห่างกัน ~190 ms ซึ่งออกแบบไว้ตอน "ฉากนิ่ง"
ถ้าเป้าเดินอยู่ ระหว่างสองรอบมันขยับไปแล้ว:

| ความเร็ว | ขยับระหว่างสองรอบ | ผล |
|---|---|---|
| 0.25 m/s | 4.7 cm | พอไหว |
| 0.5 m/s (เดินปกติ) | 9.5 cm | **เกินหน้าต่างวิเคราะห์ (±5 cm) -> คู่ที่สองพลาดเอคโค่** |

แก้ด้วย `features.PER_PAIR = True` หรือ `angle_features(..., per_pair=True)` ให้แต่ละคู่
หายอดของตัวเอง (ภายในคู่ ADC สุ่มพร้อมกัน ห่างแค่ 1.25 us จึงไม่มีปัญหาเรื่องเวลาเลย)
`train_sections.py` เทียบทั้งสองโหมดให้อัตโนมัติ จะได้ตัดสินจากข้อมูลจริง ไม่ใช่เดา

`--keep-multi` ปิดตัวกรอง "มีของใกล้หลายจุด" — ตัวกรองนั้นทำไว้ตอนเป้าเป็นท่อ PVC
แล้วขาคนเก็บติดเข้ามาในภาพ ถ้า**คนคือเป้าเอง** ไม่ต้องกรอง

## โหมดใหม่: 4 ช่องพร้อมกัน (`car/sync4.py`) — ใช้ตั้งแต่ ส.ค. 2026

`ultrasonic.Ultrasonic` ยิง 2 รอบ อ่านทีละคู่ · `sync4.Sync4` ยิง **รอบเดียวได้ครบ 4 ช่อง**

| | ยิง 2 รอบ (เดิม) | **4 ช่องพร้อมกัน (ใหม่)** |
|---|---|---|
| ระยะที่เก็บ | 258 cm | **150 cm** |
| อัตราสุ่ม | 266 kHz/ช่อง | 66 kHz/ช่อง |
| ตัวอย่าง/ช่อง | 4000 | **677** |
| ข้อมูล/ปิง | 16 KB | **5.4 KB** |
| **fps (วัดจริง)** | 2.6 -> 5.1 | **23-24** |
| คู่เบสไลน์ที่ใช้ได้ | 2 | **6** |
| เป้าเคลื่อนที่ | คู่ที่สองเพี้ยน | ไม่มีปัญหา |

### ทำไม 66 kHz ถึงใช้ได้ทั้งที่ต่ำกว่า Nyquist ของ 40 kHz
ADC ของ ESP32 มีตัวแปลงตัวเดียว อัตรารวมตันที่ ~266 kHz **ไม่ว่าจะขอเท่าไหร่**
(วัดแล้วที่ f = 500k/800k/1M/1.2M/1.6M/2M ได้ 62-66 kHz/ช่องเท่ากันหมด)
-> ใช้ **bandpass sampling**: 40 kHz พับลงมาที่ 26.4 kHz ซึ่งอยู่ใต้ Nyquist 33.2 kHz
สัญญาณเราเป็นแถบแคบ การพับจึงเป็นแค่การเลื่อนย่าน **เปลือกคลื่นและ TDOA ยังอยู่ครบ**
`features.signal_band(rate)` เลือกย่านกรองให้อัตโนมัติ (ถ้ายังกรอง 25-60 kHz จะได้แต่ศูนย์)

ราคาที่จ่าย: ความละเอียดเวลา 3.76 -> 15 us (~2.1 องศา ซึ่งยังต่ำกว่าความผิดพลาดจริง 11.8 องศา)

### จังหวะยิงคงที่
`Sync4.ping()` **รอให้ครบคาบเสมอ** แม้รอบก่อนเสร็จเร็ว คาบคำนวณจาก
`max(เวลาเสียงไปกลับ x 1.3, เวลาเก็บ + เวลาส่ง) + 3 ms` = **40.3 ms ที่ 150 cm**
เพื่อรับประกันว่าเอคโค่รอบเก่าตายสนิทก่อนรอบใหม่ (ถ้าทับกัน เอคโค่เก่าจะโผล่เป็น
"วัตถุใกล้ปลอม" ตามสูตร ระยะที่ไม่กำกวม = c x คาบ / 2)

### กรองเฉลยที่อยู่นอกระยะ
`record.py` **ข้ามเฟรมที่กล้องเห็นวัตถุใกล้สุดนอกช่วง 40-150 cm** เพราะคลื่นไม่มีข้อมูล
ระยะนั้นเลย (เช่นกล้องเห็นผนังที่ 230 cm) การเก็บไว้เท่ากับสอนโมเดลด้วยคำตอบที่ไม่มีอยู่จริง

## กฎแบบเขียนมือ (`car/rules.py`) — บอกทิศโดยไม่ใช้ ML

ใช้กับข้อมูลที่ **เดินกวาดซ้าย-กลาง-ขวาในช่วงเดียวกัน** เฉลยมาจากกล้องทีละเฟรม
ไม่ใช่จากชื่อช่วง จึงไม่ต้องยืนนิ่งทีละตำแหน่ง

```
python car/record.py --port COM5 --name walk --sections 1 --start 1 --minutes 1   # x5
python car/rules.py --name walk
```

**หลักการ**: `asym = (ฝั่งหนึ่ง - อีกฝั่ง) / (ผลรวม)` จากความแรงเอคโค่ที่ยอดเดียวกัน
หารด้วยผลรวมเพื่อให้ค่าไม่ขึ้นกับระยะ

**ใช้ความแรง ไม่ใช่ TDOA** เพราะที่ 66 kHz ความละเอียดเวลา 15 us และ TDOA พังเมื่อ
หายอดไม่ตรงกัน ส่วนความแรงใช้ได้แม้ยอดเบลอ

**ไม่ล็อกทิศทางไว้ล่วงหน้า** — เครื่องหมายของ asym เทียบกับมุมกล้องหาจากข้อมูลเอง
และรายงาน "ช่องที่แรงสุดในแต่ละโซนมุม" ให้ตรวจว่าสายต่อถูกด้าน ถ้าสลับจะเห็นทันที

ให้ผลสองแบบ: **กฎ 1** แปลง asym เป็นองศาด้วยเส้นตรง · **กฎ 2** แบ่งเป็น 5 โซน
แบ่ง train/test ตามช่วง (กันช่วงสุดท้ายไว้ทดสอบ)

> **หมายเหตุเรื่องเครื่องหมาย** (วัดแล้ว): `cam_deg` เป็น **บวกเมื่อวัตถุอยู่ครึ่งซ้ายของภาพกล้อง**
> อย่าเดาเอง — ให้ดูตาราง "ช่องที่แรงสุดแยกตามโซน" ที่ `rules.py` พิมพ์ออกมาเสมอ
