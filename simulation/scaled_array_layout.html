Scaled Array — Extended Aperture + MIMO (3 TX + 9 RX, 12 อุปกรณ์จริง)

รวม 2 การอัพเกรดที่คุยกันไว้เข้าด้วยกัน: (1) ขยาย aperture — แต่ละแขนของ Y-array เพิ่มจาก 2 เป็น 3 ตัวรับ (40 / 80 / 140mm ตัวใหม่) และ (2) MIMO — จาก TX เดี่ยวกลางแผง เป็น 3 TX แบบ coded วางเป็นกลุ่มเล็กกึ่งกลาง (ระยะห่างกันเองพอให้ตัวถัง 16mm ไม่ชนกัน) รวมเป็น 3×9 = 27 เส้นทางข้อมูลเสมือน จากอุปกรณ์จริงแค่ 12 ตัว

ผังด้านล่างนี้คือแบบเต็ม — ใช้ได้กับ ESP32 + ADS1115 (hybrid) เท่านั้น ตามที่สรุปไว้ในตาราง งบประมาณช่องสัญญาณด้านล่าง Nano และ ESP32 เดี่ยวไม่มีช่องพอสำหรับ 9 RX เต็มรูปแบบ ต้องตัดทอนลง — ดูผังที่ตัดแล้วจริงของแต่ละแพลตฟอร์มได้ในหัวข้อ "ผังตามแพลตฟอร์ม" ถัดจาก Diminishing Returns

ผังตามแพลตฟอร์ม (มาตราส่วนเดียวกัน เทียบขนาดตรงๆ ได้)

Arduino Nano — 1 TX + 6 RX ตัดเหลือน้อยสุด

ตัด TX เหลือ 1 ตัว (กลางแผงพอดี) + ตัดตัวรับ "far" 140mm ออกทั้ง 3 แขน เหลือ near/mid เดิม 40/80mm

ESP32 เดี่ยว — 3 TX + 8 RX ตัด 1 ตัว

เก็บ TX ครบ 3 ตัว + RX ครบ 3 ตัว/แขน (near/mid/far) ไว้ 2 แขน ส่วนอีก 1 แขนตัด far ออก เหลือแค่ near/mid

ESP32 + ADS1115 — 3 TX + 9 RX เต็มรูปแบบ

ครบทุกตัวตามที่ออกแบบไว้ — RX "far" ทั้ง 3 (จุดสีม่วง) ต่อผ่าน ADS1115 แบบ envelope-only

งบประมาณช่องสัญญาณ 3 แพลตฟอร์ม (Nano / ESP32 / ESP32+ADS1115)

Arduino Nano ไม่พอ

ขา ADC ทั้งหมด8 (A0-A7)
RX ที่ใส่ได้จริง≤6-7 ตัว (เหลือขาไว้คุม TX/TRIG)
อัตรา sample ต่อช่อง~10-13 kS/s (ADC เดียว มัลติเพล็กซ์)
จับ raw chirp 40kHz ได้ไหมไม่ได้ (ต้องการ >80kS/s/ช่อง)
MIMO coded TXไม่ไหว (ประมวลผลจำกัด)
แนะนำ: ตัด TX เหลือ 1 ตัว, RX เหลือ 6 ตัว (arm ละ 2, กลับไปที่ 40/80mm เดิม ตัด 140mm ออก) ใช้โหมด envelope+threshold (แบบที่ทดสอบผ่านแล้วตอนต้น) ไม่ใช่ raw chirp — นี่คือ Phase 1 ที่ทำงานได้จริงบน Nano

ESP32 เกือบพอ

ADC1 (ใช้ตอน WiFi เปิด)8 channel
ADC2 (ชนกับ WiFi)10 channel (เสี่ยงถ้าใช้ WiFi ด้วย)
RX ที่ใส่ได้จริง (ไม่พึ่ง ADC2)8 ตัว (ยังขาด 1 จาก 9 ที่ออกแบบไว้)
อัตรา sample ต่อช่อง (DMA)~100-500 kS/s — พอสำหรับ chirp
จับ raw chirp 40kHz ได้ไหมได้
MIMO coded TX3 ตัวได้เต็มรูปแบบ
แนะนำ: 3 TX + 8 RX (ตัด far ออก 1 ตัวจาก 3 แขน เหลือ 2 แขนที่มี far, หรือใช้ ADC2 อีก 1 ช่อง ถ้ายอมเสี่ยง WiFi กระตุก) — เพียงพอสำหรับ Phase 2-3 เต็มรูปแบบ (MIMO + chirp/pulse compression)

ESP32 + ADS1115 ครบ 3TX+9RX

ช่องเพิ่มจาก ADS1115 (I2C)4 channel
ความเร็ว ADS1115~860 SPS เท่านั้น (ช้ามาก)
จับ raw chirp บน ADS1115 ได้ไหมไม่ได้เด็ดขาด (ช้ากว่าที่ต้องการ >100 เท่า)
ใช้ทำอะไรได้envelope (สัญญาณช้าหลัง detector) เท่านั้น
MIMO coded TX3 ตัว (ใช้ ESP32 ควบคุม)
แนะนำ (hybrid): ใช้ ESP32 ADC1 จับ raw waveform 8 ช่อง (near+mid ทั้ง 3 แขน = 6 ช่อง + far อีก 2) สำหรับ chirp/pulse-compression เต็มรูปแบบ ส่วน RX "far" 140mm ที่เหลือ (3 ตัว) ต่อผ่าน ADS1115 แบบ envelope-only (หยาบกว่า แต่พอบอกว่ามี/ไม่มีวัตถุระยะไกลได้) — ครบทั้ง 3TX+9RX ตามที่ออกแบบไว้ แต่คุณภาพข้อมูลไม่เท่ากันทุกช่อง
