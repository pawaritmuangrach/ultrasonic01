# รอบ 3 — สิ่งที่จะแก้ และชุดข้อมูลใหม่

บันทึกไว้ก่อนเก็บข้อมูล จะได้ไม่ลืมว่าจะแก้อะไรและทำไม

## ชุดข้อมูลใหม่ — และทำไมมันแก้ปัญหาใหญ่ของรอบ 2

**แผน: 5 ช่วง ช่วงละ 5 นาที ทำอะไรก็ได้ แต่ทำเหมือนกันทุกช่วง**

รอบ 2 พังตรงนี้: **หนึ่งช่วง = หนึ่งตำแหน่ง** กันช่วงหนึ่งไว้ทดสอบจึงเท่ากับ
กันตำแหน่งนั้นออกจากการเทรนทั้งหมด โมเดลต้องเดาข้ามไปยังที่ไม่เคยเห็น
หลักฐาน: แม้แต่แม่แบบที่รู้ตำแหน่งจริงยังได้ R2 ติดลบ 0.713

ต้องเลี่ยงด้วยการแบ่งตามเวลา (กัน 25% ท้ายของทุกช่วง) ซึ่งใช้ได้ แต่ยังมีจุดอ่อน
เพราะเฟรมทดสอบอยู่ในเซสชันเดียวกับเฟรมเทรน เสื้อผ้าเดิม ห้องเดิม แสงเดิม

**ชุดใหม่ทุกช่วงครอบคลุมเหมือนกัน จึงกันทั้งช่วงไว้ทดสอบได้ตรง ๆ**
เป็นการทดสอบที่สะอาดกว่า และเป็นวิธีที่ควรใช้ตั้งแต่แรก

## ข้อกังวลข้อเดียวของแผนนี้ — และวิธีกัน

"ทำอะไรก็ได้" ให้ **ตำแหน่ง** หลากหลายดี แต่มีโอกาสให้ **ท่าทาง** น้อยลง
ถ้าเดินไปมาเฉย ๆ ส่วนใหญ่จะเป็นท่ายืน ซึ่งเป็นท่าเดียวกันหมด

แต่เป้าหมายของเราคือให้เห็นท่ากางแขนกับท่าย่อตัว ถ้าข้อมูลมีท่าพวกนั้นน้อย
โมเดลก็เรียนไม่ได้ ไม่ว่า loss จะดีแค่ไหน

**ทางแก้: เปิดคิวท่าไว้ด้วย (`--poses`) แล้วเดินเปลี่ยนที่ไปด้วยระหว่างทำท่า**
จะได้ทั้งตำแหน่งหลากหลายและท่าหลากหลายในช่วงเดียวกัน

คำสั่งที่จะใช้

```
python car/record.py --port COM5 --name mix --sections 5 --minutes 5 --poses
```

- `--name mix` สำคัญ · `mapdata2.ROUNDS["r3"]` รอชุดชื่อ `mix_s1` ถึง `mix_s5`
- ขาไม่ต้องใส่แล้ว ค่าปริยายเป็น `35,34,32,33` ตรงกับ rig2 แล้ว
- ได้ราว 4,200 เฟรมต่อช่วง รวม ~21,000 เฟรม ใกล้เคียงรอบ 2 (22,375)

## แยกที่เก็บของแต่ละรอบแล้ว

ทำไปแล้วก่อนเก็บข้อมูล เพราะถ้าสร้างแคชทับ ข้อมูลกับโมเดลรอบ 2 จะหายทั้งคู่

| รอบ | ชุดข้อมูล | แคช | โมเดล |
|---|---|---|---|
| r2 | pose_s1-5 + free_s1-3 | `_map2_cache` | `_map2_model.pt` |
| **r3** | **mix_s1-5** | `_map2_cache_r3` | `_map2_model_r3.pt` |

ค่าปริยายคือ r3 · กลับไปใช้ของเก่าด้วย `MAP2_ROUND=r2`

## สี่อย่างที่จะแก้ตอนเทรน

เรียงตามผลกระทบที่คาดว่าจะได้ · **ทั้งสี่ข้อยังไม่ได้ทดลอง** เป็นการวิเคราะห์ว่า
loss ไม่ตรงกับสิ่งที่เราวัด ไม่ใช่ผลที่วัดมาแล้ว

### 1. เพิ่มพจน์ความสูงเงาเข้า loss

**ปัญหา: เราวัดท่าทางแต่ไม่เคยสอนท่าทางเลย** loss ปัจจุบันไม่มีคำว่าความสูง
อยู่เลยแม้แต่คำเดียว โมเดลจึงไม่เคยถูกบอกว่าท่าทางสำคัญ

```python
h_p = shadow_height(sigmoid(ol))
h_t = shadow_height(occ)
loss = bce + 2.0*l1 + 0.5*|h_p - h_t|
```

น่าจะได้ผลมากที่สุด เพราะตรงกับเป้าหมายที่ตั้งไว้ที่สุด

### 2. เพิ่ม Dice เข้าไปคู่กับ BCE

**ปัญหา: วัด IoU แต่สอนด้วย BCE ซึ่งเป็นคนละอย่าง**

วัดจากข้อมูลจริง: ช่องที่มีวัตถุเฉลี่ยแค่ **26.7%** ของภาพ
ทายว่า "ว่างทั้งภาพ" อย่างเดียว BCE ก็ดูดีเพราะถูก 73.3% ของช่อง
**แต่ IoU จะเป็นศูนย์** BCE ให้น้ำหนักทุกช่องเท่ากัน จึงถูกครอบงำด้วยพื้นหลัง

```python
dice = 1 - 2*(p*occ).sum() / (p.sum() + occ.sum() + 1)
loss = bce + dice + 2.0*l1
```

### 3. เลือกเช็คพอยต์ด้วย R2 ไม่ใช่ IoU

ตอนนี้เก็บรอบที่ IoU ดีที่สุด ซึ่งอาจทิ้งรอบที่ท่าทางดีกว่าไป
รอบ 2 เห็นชัด: รอบที่ 28 ได้ R2 -0.016 แต่รอบที่เก็บไว้ได้ -0.143

ควรเก็บทั้งสองแบบไว้เทียบ หรือเลือกด้วยคะแนนรวมที่ให้น้ำหนักท่าทางด้วย

### 4. ลองน้ำหนักของ l1 หลายค่า

เลข 2.0 ผมตั้งขึ้นมาเอง ไม่ได้ทดลอง · ควรลอง 1.0 / 2.0 / 4.0 แล้ววัด

## เรื่องฮาร์ดแวร์ที่เจอระหว่างวิเคราะห์ — ไม่เกี่ยวกับรอบนี้แต่ต้องจด

**สัญญาณใช้ไปแค่ 7.3 บิต จาก 12 บิตที่ ADC มี**

| | ค่า |
|---|---|
| ช่วงที่ ADC ให้ได้ | 0 - 4095 |
| ที่ใช้จริง | 1437 - 2318 |

ใช้ไป **3.9%** ของช่วง ADC · จุดสูงสุดถึง 451 แปลว่า **เพิ่มอัตราขยายได้อีก
ราว 4.5 เท่าก่อนล้น** ซึ่งจะได้ความละเอียดเพิ่มอีก 2.2 บิต

แก้ที่บอร์ด ไม่ใช่ที่โมเดล · จดไว้ใช้ตอนออกแบบบอร์ดรุ่นถัดไป
